# 发布前变更确认：设计讨论

## 本轮目标

把单条发布前变更确认做成一个可建造、可验证的最小工作台，验证产品经理能否在同一处完成查看、确认和回看。

## 已知上下文

- 产品级 Proposal 已确认：首版不做多人协作、审批编排、权限体系、外部集成或 AI 摘要。
- 主用户是产品经理，触发时刻是准备发布一条产品变更。
- MVP 必须证明确认动作完成、刷新后状态保持、确认时间可回看。

## 本轮决定

- 状态模型采用“待处理 / 已确认”两态。
- 产品经理可以确认，也可以保留待处理；系统记录状态和确认时间。
- 本轮不引入退回状态、评论、审批人或自动判断。
