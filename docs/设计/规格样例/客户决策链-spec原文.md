# 客户决策链 — 新标准从零产出样例（agent 最终版）

==================== 【探索小结】 ====================

**真正要解决的问题**：销售在一个客户里跟很多人打交道，但脑子里那张"谁是谁、谁向着我、谁拦着我、谁说了算"的图是隐性的、散在记忆和聊天记录里的，新人接手或者临时支援的同事完全看不到。结果就是劲使错了地方——天天陪着一个其实不拍板的人喝茶，真正的决策者反而没碰过。所以这个模块的核心价值不是"画个组织图"，而是把这张隐性的人际地图显性化、可交接，并且让商机专家 Agent 能基于这张图给出"下一步该攻谁"的具体建议。

**这是哪一类需求**：主体是**信息密集 UI 卡**（把一个客户的一群人和他们的角色、态度、关系收在一个地方，一行代表一个干系人），但它强绑了一层 **Agent·引擎**（攻关建议、态度风险预警都是 Agent 算出来的派生信息）。所以按"信息密集 UI 卡 + Agent 派生信息"双类型写：信息模型那段重点写一行是什么、上卡放什么、三种身份怎么分；Agent 那段重点写攻关建议和风险提示怎么算、什么时候重算、会不会盖掉人改的。

**我做的关键假设**（这些是我自己定的，不是 PM 拍过的）：
- 干系人挂在**客户**下，不挂在单个商机下——一个客户里这群人，对同一客户的多个商机大体是同一拨，所以以客户为单位维护，商机里引用。
- 干系人信息**主要靠销售自己手填**，Agent 在旁边补充建议（比如从商机往来记录里发现一个没录入的新名字，提醒"要不要加进来"），但不自动凭空建人。
- 态度分**支持 / 中立 / 反对 / 不明**四档，角色分**决策者 / 影响者 / 使用者 / 反对者 / 其他**——这是销售场景里最常用的一套，但具体几档、叫什么名，得 PM 认。
- 关系先做**人与人之间的有向关系**（谁是谁的上级、谁和谁是盟友、谁俩不和），不做复杂的组织树。
- "攻关建议""态度风险"是 Agent 给的**提示**，不是硬指令，销售可以不理。

**该问 PM 拍板的未决问题**（逐条）：
1. 干系人到底挂客户下还是商机下？如果一个客户有好几个商机、对接人差别很大，挂客户下会不会太糙——这条直接决定信息模型，得先定。
2. 态度和角色的分档，用我这套（态度四档 / 角色五类）行不行？要不要加"态度变化趋势"（在变好还是变差）？
3. Agent 凭往来记录"发现新干系人"这个能力，要不要做？涉及它去读销售的聊天 / 邮件，边界敏感，得 PM 点头。
4. 这张图要不要给团队里别人看（主管、支援的同事）？如果要共享，那"谁向着我谁反对"这种敏感判断写在上面，合不合适、要不要分可见范围？
5. Agent 算"该攻谁"时，凭什么算——只看态度和角色，还是要把"这人最近有没有被接触过""商机到哪个阶段了"也算进去？算法口径要 PM 认一版。

## 一、概述

这份文档定"客户决策链"这个模块要做成什么样：它是什么、谁用、什么时候用、人能在上面做什么、商机专家 Agent 在上面算什么。不定原型长什么样，那交给后面的 mock。

## 二、名词解释

| 术语 | 含义 |
| --- | --- |
| 客户 | 我们在跟的一家公司（甲方单位）。 |
| 商机 | 针对某个客户的一笔具体生意，分四个阶段——初步接触、需求梳理、方案设计与验证、报价谈判。 |
| 干系人 | 客户那边和这笔生意有关的人，比如对接人、部门领导、最终拍板的人。 |
| 角色 | 这个干系人在客户内部对这笔生意起什么作用，比如能拍板的、能影响别人的、将来要用的。 |
| 态度 | 这个干系人现在对我们是什么立场——向着我们、无所谓、反对、还看不清。 |
| 关系 | 两个干系人之间是什么关系，比如上下级、是一伙的、彼此不和。 |
| 决策链 | 一个客户里所有干系人加上他们之间的关系合起来这张图，看明白"谁说了算、谁帮我、谁拦我"。 |
| 商机专家 Agent | 后台一直看商机数据、给销售出主意的助手，下面简称 Agent。 |
| 攻关建议 | Agent 给出的"现在该重点搞定谁"的提示。 |
| 态度风险 | Agent 发现某个关键的人态度不妙、可能坏事时给出的提醒。 |

## 三、用户与场景

客户决策链是挂在一个客户下面的一块地方，把这个客户里所有相关的人、他们各自的角色和态度、以及他们之间的关系，都收在一处。销售一眼能看明白：这家客户里谁说了算、谁在帮我、谁在挡我，接下来劲该往谁身上使。

主要是销售用。售前和架构师跟着商机进来时，也能看这张图，知道客户那边的人际格局，不用再口头问销售一遍。

什么时候用：跟进一个客户、准备见客户、商机要往前推一个阶段、或者新人接手一个客户的时候，都会来看这张图、顺手更新一下。

## 四、信息模型

### 4.1 一行放什么

决策链里一个人占一行。一行上能看到这个人的：

- 名字
- 在客户那边的职位 / 部门（比如"信息中心主任"）
- 角色——决策者 / 影响者 / 使用者 / 反对者 / 其他，这个人对这笔生意起什么作用
- 态度——支持 / 中立 / 反对 / 不明
- 跟我们这边谁对接（我方负责接触他的人）
- 最近一次接触是什么时候

点开这一行，能看到更细的：这个人和别人之间的关系、历史接触记录的简单备注、销售自己写的判断（"这人嘴上不说，其实很关键"）。

### 4.2 信息的三种身份

每条信息旁边要能看出来它是怎么来的，分三种：

- **销售自己填的 / 确认过的**：以这个为准。
- **Agent 建议的、人还没确认**：Agent 觉得可能是这样（比如从往来记录里猜这个人是决策者），摆在那等销售点头或否掉。销售没处理之前，这条不算数。
- **Agent 算出来的提示**：像攻关建议、态度风险，这类是 Agent 给的判断，不是客户的客观事实，要和上面两种分开，让人一眼知道这是"机器的看法"。

## 五、核心动作

| 动作 | 做什么 |
| --- | --- |
| 加一个干系人 | 销售手动新建一个人，填名字、职位、角色、态度这些。 |
| 改一个干系人 | 随时改他的角色、态度、对接人、备注。改完以这个为准。 |
| 连一条关系 | 把两个人连起来，标明是什么关系——上下级（谁管谁）、盟友（一伙的）、不和。关系是有方向的，比如"张三是李四的上级"。 |
| 删一个干系人 / 一条关系 | 这个人离职了、或者发现根本不相关，删掉。 |
| 处理 Agent 的建议 | Agent 建议加某个人、或建议把某人标成决策者，销售可以**采纳**（变成自己确认的）或**否掉**（这条建议消失，Agent 短期内不再重复提同一条）。 |
| 看攻关建议和态度风险 | Agent 给的提示摆在显眼地方，销售可以照着做，也可以不理；不理的提示可以**收起**，不一直占着地方。 |

## 六、Agent 计算逻辑

这一块是 Agent 的派生信息。每一项都说清四件事：从哪来、怎么算、什么时候重算、重算会不会盖掉人改的。

### 6.1 攻关建议：现在该重点搞定谁

- **从哪来**：基于这个客户决策链里已有的干系人——他们的角色、态度，加上商机当前在哪个阶段、每个人最近被接触过没有。
- **怎么算**：Agent 找出那种"分量重、但还没搞定"的人，优先推出来。一个人越是能拍板（决策者 / 影响者）、态度越是还没到位（中立 / 反对 / 不明）、又越是好久没被接触过，就越该被重点攻关。商机到了越靠后的阶段（方案设计与验证、报价谈判），决策者和反对者的权重越高，因为这时候拍板的人和挡事的人最要命。Agent 把最该攻的一两个人推出来，并说一句为什么（"信息中心主任是这单的决策者，态度还不明，而且三周没接触了"）。
- **什么时候重算**：干系人的角色 / 态度被改了、加了或删了人、关系变了、商机阶段往前走了、或者记录了一次新的接触，都会让 Agent 重新算一遍。
- **会不会盖掉人改的**：不会盖人填的客户事实（角色、态度这些是销售说了算）。攻关建议本身是 Agent 每次重算重新给的提示，不是人编辑的内容，所以重算时直接刷新。但如果销售把某条建议**否掉**了，重算时 Agent 不会马上又把同一条顶回来。

### 6.2 态度风险：谁的态度有风险

- **从哪来**：基于干系人的角色和态度。
- **怎么算**：Agent 盯那些"位置重要但态度不友好"的人。一个决策者或关键影响者，如果态度是反对、或者一直不明，就算一条态度风险，提醒销售这人可能坏事、得重视。如果客户里有人明确是反对者，也单独拎出来提醒。
- **什么时候重算**：相关干系人的角色或态度一改，就重新算。
- **会不会盖掉人改的**：同样不动人填的事实。风险提示是 Agent 给的判断，重算时刷新；销售收起或忽略掉的提示，短期内不反复弹。

### 6.3 Agent 建议补一个没录入的人（待 PM 拍板是否做）

如果做这个能力：Agent 从商机往来记录里发现一个决策链上还没有的名字，会建议销售"要不要把这个人加进来"。这只是个待确认的建议，销售点头才真的建人；不会自己凭空把人加进图里。这条涉及 Agent 去读往来记录，边界敏感，先列出来等 PM 定做不做。

## 七、状态机

这张图不是只有"人都填好了、Agent 也算好了"这一种样子。下面这几种都要照顾到：

- **空的时候**：一个客户刚建、还没录任何干系人。这时候这块地方要引导销售"先把客户那边的关键人加进来"，而不是空白一片让人不知道干嘛。
- **正在算**：销售刚改完一批信息，Agent 还在重算攻关建议和态度风险。这段时间提示区要让人知道"正在重新算"，别显示半截的旧结果还装作是新的。
- **提示基于旧情况、该重算了**：信息已经改了但还没算完，旧的攻关建议要标出来"这是基于改之前的情况，正在更新"，别让销售照着过时的建议去行动。
- **信息打架、要销售定**：同一个人，销售之前填的态度和 Agent 从记录里判断的态度不一样（比如人填"支持"、Agent 觉得"反对"）。这时候不偷偷改人填的，而是把这处分歧摆出来，让销售自己看一眼、定哪个对。
- **销售锁过的**：某个判断销售很笃定、不想被 Agent 反复建议来回烦（比如"这人就是决策者，别再问了"），可以锁住。锁住之后 Agent 不再对这条出建议，只在旁边安静记着自己的不同看法，不打扰。

## 八、验收标准

下面每条都能单独验。

1. 在一个客户下能进到"客户决策链"这块地方，看到这个客户已有的干系人列表。
2. 能手动加一个干系人，填名字、职位、角色、态度、对接人，加完出现在列表里。
3. 能改一个已有干系人的角色、态度、对接人、备注，改完以新填的为准。
4. 能把两个干系人连一条有方向的关系（上下级 / 盟友 / 不和），也能删掉这条关系。
5. 能删掉一个干系人，删掉后他和别人的关系也一起没了。
6. 每条干系人信息能看出来是"销售确认的""Agent 建议待确认"还是"Agent 算的提示"这三种里的哪种。
7. Agent 能根据角色、态度、商机阶段、最近接触情况，推出"现在该重点攻关谁"，并给一句为什么。
8. 改了某个人的角色或态度后，攻关建议和态度风险会跟着重新算，刷出新的结果。
9. Agent 能对"位置重要但态度反对 / 一直不明"的关键人给出态度风险提醒。
10. 销售能采纳或否掉 Agent 的一条建议；否掉后短期内同一条建议不再反复出现。
11. Agent 重算攻关建议和态度风险时，不会改动销售自己填的角色、态度、备注。
12. 当销售填的态度和 Agent 判断的态度不一致时，系统把这处分歧摆出来让销售定，而不是自动改掉销售填的。
13. 客户还没有任何干系人时，这块地方给出引导，而不是一片空白。
14. 销售改完信息、Agent 还在重算的这段时间，提示区能让人知道正在重算，旧提示标明是基于改之前的情况。
15. 销售能锁住某个判断，锁住后 Agent 不再对这条反复出建议。
