# 团队成员与角色权限管理（轻风格版）

| 项目 | 内容 |
| --- | --- |
| 模块名 | 团队成员与角色权限管理 |
| 版本 | V1.0 |
| 状态 | 待评审 |
| 日期 | 2026-06-20 |

## 一、概述

这是 SaaS 后台里管人的地方。团队里的人分三种角色，权限从大到小是所有者、管理员、普通成员。这个模块要做的事：把团队里所有人和还没接受的邀请都摆出来，让有权限的人去邀请新人、改别人角色、移除人，让所有者能把团队交给别人，也让每个人能自己退出团队。

一条底线贯穿全文：一个团队，任何时候都只有一个所有者，不多不少。

## 二、名词解释

| 术语 | 含义 |
| --- | --- |
| 所有者 | 团队里权限最高的那个人，一个团队只有一个。能做所有事，包括把团队转给别人。不能被移除，也不能被降级，除非他先把所有权转走。 |
| 管理员 | 能管人的角色。可以邀请人、移除人、改别人角色、看全部成员。但碰不了所有者。 |
| 普通成员 | 权限最小。只能看成员列表，看完就完了，不能做任何管理动作。 |
| 成员 | 已经接受了邀请、正式在团队里的人。 |
| 邀请 | 发给某个邮箱的入队请求。对方本人接受了才算成员，没接受之前不算。 |
| 状态 | 一个人或一条邀请现在的处境：正常、已禁用、待接受、已过期。 |
| 转移所有权 | 所有者把自己手上的最高权限交给另一个人。 |

## 三、用户与场景

| 谁 | 来干什么 |
| --- | --- |
| 所有者 | 管整个团队，包括最后把团队交出去。 |
| 管理员 | 帮所有者管人：拉人进来、改角色、清退普通成员。 |
| 普通成员 | 就是来看看团队里都有谁，不参与管理。 |

## 四、核心动作

### 4.1 看成员列表

进来就是一份名单，列出每个人的姓名、邮箱、角色、状态、加入时间。

还没接受的邀请也放在这同一份名单里，正式成员排在上面，待接受的邀请排在下面。

名单上面可以搜，搜的是姓名和邮箱这两样，输角色名或者状态名是搜不到的。

旁边还有两个筛子：

- 按角色筛：全部、所有者、管理员、普通成员。
- 按状态筛：全部、正常、已禁用、待接受、已过期。

搜索和这两个筛子能一起用，叠起来的结果是同时满足三个条件的那批人。

普通成员也能看这份名单、也能搜也能筛，跟别人看到的内容一样。区别只在：普通成员看到的每一行后面，都没有任何管理用的按钮。

### 4.2 邀请成员

列表页上有个 [邀请成员]。普通成员看不到这个按钮。

点开之后填两样东西：对方的邮箱，给他的角色。

角色这里有讲究：

- 不管谁来邀请，都不能把人邀请成所有者。所有者只能靠转移所有权产生。
- 所有者来邀请，可以选管理员或普通成员。
- 管理员来邀请，只能选普通成员，不能拉人进来当管理员。

填的时候有几道拦：

- 邮箱没填、或者填得不像个邮箱，[发送邀请] 是点不动的，会提示把邮箱填对。
- 这个邮箱已经是团队成员了，拦下来，告诉你这人已经在团队里了。
- 这个邮箱已经有一条还没接受的邀请挂着了，也拦下来，告诉你已经发过了，想动它就去名单里重发或者撤销。
- 如果这个邮箱以前那条邀请已经过期了，或者被撤销了，那这次可以正常重新邀请。

发出去之后，名单里就多一行"待接受"的邀请。

### 4.3 接受邀请

只有被邀请的本人去接受了，他才正式变成成员，角色就是当初邀请时定好的那个。

在他接受之前，他不算团队成员，也不占团队的成员名额。

如果一条邀请放到过了有效期都没人接受，它就变成"已过期"。已过期的邀请不能再被接受了，对方想进来得重新发一条。

### 4.4 重发和重新邀请

- 一条"待接受"的邀请，那行有 [重发]，点了就再催一次。
- 一条"已过期"的邀请，那行不是 [重发] 而是 [重新邀请]，点了等于对这个邮箱重新发一条新的。
- 已经是正式成员的那些行，没有这两个按钮，他人都进来了不用再发。

### 4.5 撤销邀请

一条"待接受"的邀请，那行有 [撤销]。

点 [撤销] 要再确认一次。确认完，这条邀请就从名单里消失了。

撤销之后这个邮箱就空出来了，想再请他可以重新邀请。

### 4.6 改成员角色

成员那行有改角色的入口。普通成员看不到这个入口。

能改的范围：在管理员和普通成员这两个角色之间互相换。

几条不能做的：

- 谁都不能被改成所有者。想让某个人当所有者，只有一条路，就是转移所有权。
- 所有者的角色不能改，所有者那行根本没有改角色的入口。
- 管理员不能把别人提到比自己还高的位置，所以管理员去改别人角色时，"所有者"这个选项对他来说是没有的。
- 管理员也不能给自己提权，所以管理员自己那一行，没有改角色的入口。
- 所有者就随意了，团队里除了所有者本人，任何人的角色他都能改。

改完之后，那一行的角色马上就变成新的。

### 4.7 移除成员

成员那行有 [移除]。普通成员看不到。

点 [移除] 要再确认一次，确认时要把话说明白：这人会立刻失去对这个团队的访问，而且这个动作做了就撤不回来。

谁能移除谁：

- 所有者不能被移除，所有者那行没有 [移除]。
- 管理员只能移除普通成员，移不了所有者，也移不了别的管理员。
- 所有者能移除任何管理员和任何普通成员。

### 4.8 退出团队

每个人自己那一行有 [退出团队]，其实就是把自己移除掉。

点了要再确认一次。本人确认了就生效，不用谁来批。

但所有者没有 [退出团队]。所有者要走人，得先把所有权转给别人、让自己降成管理员，然后才能退。

### 4.9 转移所有权

[转移所有权] 这个按钮只有所有者看得到。

点开之后选一个接手的人。这里只能从现在的管理员里挑，普通成员不在可选范围里。

如果团队里现在一个管理员都没有，这个按钮是点不动的，会提示你先把某个人设成管理员，再回来转。

选好接手人之后，给一句分量重的提醒：转完之后你自己就降成管理员了，对方会拿到团队的全部权限，而且这个事撤不回来。

为了防手滑，还要你手动把"转移所有权"这几个字一个字一个字打进去，[确认转移] 才点得动。

确认之后：原来的所有者变成管理员，接手的人变成所有者。团队还是只有一个所有者。原来那个人转完立刻就没有所有者专属的那些能力了。

## 五、状态与边界

### 5.1 成员和邀请的状态

| 状态 | 说的是 | 谁会是这个状态 |
| --- | --- | --- |
| 正常 | 在团队里、能正常用 | 成员 |
| 已禁用 | 在团队里、但被停掉了用不了 | 成员 |
| 待接受 | 邀请发出去了、还没人接 | 邀请 |
| 已过期 | 邀请放过了有效期、没人接 | 邀请 |

### 5.2 一个团队只有一个所有者

这是这个模块最硬的一条规矩，任何动作做完都得守住：

- 不能凭空多出第二个所有者，所以邀请和改角色都没法把人变成所有者。
- 也不能一个所有者都没有，所以所有者不能被移除、不能被降级、不能直接退出，他想腾出这个位置只能转给别人。
- 转移所有权是唯一一个换所有者的口子，转的过程是一进一出，转完还是正好一个。

### 5.3 两个人同时动同一个对象

两个人差不多同时去操作同一个人或同一条邀请的时候，谁先生效就按谁的来。后到的那一个会失败，告诉他这个对象已经被人动过了，然后把名单刷新成最新的样子让他重新看。

### 5.4 权限变化马上算数

角色一改、人一移除、所有权一转，权限立刻就是新的，不用等、不用刷。原来能点的按钮该没就没，原来不能点的该有就有。

### 5.5 撤不回的动作要讲清楚

移除成员、撤销邀请、转移所有权，这三件做了就回不去。确认的时候都要明明白白写出"撤不回"，别让人糊里糊涂点下去。

### 5.6 失败要说为什么

任何动作没成，不能只甩一句"失败了"。得说清楚到底是因为啥，比如对方已经被别人移除了、这个邮箱已经是成员了、团队里没有管理员可转。

### 5.7 空的和边界的情况

- 团队里只有所有者一个人的时候：名单就这一行，没有 [退出团队]，[转移所有权] 因为没有管理员可选所以点不动。
- 一条待接受的邀请都没有的时候：名单里就只有正式成员，不显示邀请那一截。
- 一个人都搜不到 / 筛不出来的时候：给一个找不到结果的提示，别留一片空白。

### 5.8 用词统一

整个产品里，这三种角色就固定叫所有者、管理员、普通成员；那四种状态就固定叫正常、已禁用、待接受、已过期。不换着叫别的说法。

## 六、验收标准

| 编号 | 场景 | 期望结果 |
| --- | --- | --- |
| 1 | 进列表页 | 成员排上、待接受邀请排下，每行能看到姓名、邮箱、角色、状态、加入时间 |
| 2 | 在搜索框输姓名或邮箱 | 能搜到对应的人；输角色名或状态名搜不到 |
| 3 | 同时用搜索 + 角色筛 + 状态筛 | 出来的是三个条件都满足的那批 |
| 4 | 普通成员看列表 | 能看、能搜、能筛，但每行都没有任何管理按钮，也看不到 [邀请成员] 和 [转移所有权] |
| 5 | 邮箱填空或格式不对 | [发送邀请] 点不动，提示把邮箱填对 |
| 6 | 邀请一个已经是成员的邮箱 | 拦下来，提示这人已在团队里 |
| 7 | 邀请一个已有待接受邀请的邮箱 | 拦下来，提示已发过、可去名单重发或撤销 |
| 8 | 邀请一个之前已过期或被撤销过的邮箱 | 能正常重新邀请 |
| 9 | 管理员发邀请 | 角色只能选普通成员，选不到管理员，也选不到所有者 |
| 10 | 所有者发邀请 | 角色能选管理员或普通成员，选不到所有者 |
| 11 | 发出邀请后 | 名单多一行"待接受"的邀请 |
| 12 | 被邀请人本人接受 | 他变成成员，角色是当初定的那个；接受前不算成员、不占名额 |
| 13 | 邀请过了有效期没人接 | 变成"已过期"，且不能再被接受 |
| 14 | 待接受邀请那行 | 有 [重发] 和 [撤销] |
| 15 | 已过期邀请那行 | 有 [重新邀请]，没有 [重发] |
| 16 | 点 [撤销] 并确认 | 这条邀请从名单消失，之后该邮箱可重新邀请 |
| 17 | 管理员改别人角色 | 能在管理员和普通成员之间换，选不到所有者；自己那行没有改角色入口 |
| 18 | 所有者改别人角色 | 任何非所有者成员都能改，但改不成所有者 |
| 19 | 所有者那行 | 没有改角色入口、没有 [移除]、没有 [退出团队] |
| 20 | 管理员点 [移除] | 只能移普通成员，移不了所有者和其他管理员；确认时说明"立刻失去访问且撤不回" |
| 21 | 所有者点 [移除] | 能移任何管理员和普通成员 |
| 22 | 任何非所有者点 [退出团队] 并确认 | 本人确认即生效，自己被移出团队 |
| 23 | 团队没有任何管理员时点 [转移所有权] | 点不动，提示先设一个管理员 |
| 24 | 转移所有权选接手人 | 只能从管理员里选，普通成员选不到 |
| 25 | 转移所有权确认前 | 要手动打入"转移所有权"几个字，[确认转移] 才点得动；并提示转完自己降为管理员、对方拿全部权限、撤不回 |
| 26 | 转移所有权确认后 | 原所有者变管理员、接手人变所有者，团队仍只有一个所有者，原所有者立刻失去专属能力 |
| 27 | 两人同时动同一个对象 | 先生效的算数，后一个收到失败提示并刷新名单 |
| 28 | 任意动作做完 | 权限立刻按新的算 |
| 29 | 任意动作失败 | 给出具体原因，不是只说"失败" |
| 30 | 团队只有所有者一人 | 名单只一行、无 [退出团队]、[转移所有权] 点不动 |
| 31 | 没有任何待接受邀请 | 名单只显示正式成员 |
| 32 | 搜索或筛选没有结果 | 给找不到结果的提示，不留空白 |
