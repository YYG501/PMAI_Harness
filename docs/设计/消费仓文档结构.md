# 消费仓文档结构（瘦身改造 v2 后的新布局）

> **这是什么**：框架瘦身改造（吸收 ExampleAgentProject 设计方法）后，**消费仓里文档怎么摆**的权威定义。一棵 `docs/` 树装下所有真相源，取消 `requirements/active|closed/` 整棵树，模块成为唯一组织单位。
> **状态**：定义稿（随改造方案落地）。设计源 = `docs/设计/吸收ExampleAgentProject设计方法-改造方案.md` §3 / §5 / §6。
> **谁读**：消费仓 AI 在新建 / 归位任何文档前对一眼本表；做 lifecycle 迁移的 agent 照本文「留给迁移的接口」搬家；PM 想知道"这东西该放哪"也看它。
> **一句话**：**当前产品长什么样看脊柱（`PRODUCT-STATE`）；一个模块的一切看 `docs/modules/<模块>/`；为什么这么拼看 `decisions.md` / `PRODUCT-RULES`；想做没做的看 `TODO`；上传的材料按类型落 `docs/inputs/<类别>/`；探过的视觉看 `mocks/`。**

## 〇、和旧布局的根本差别

| | 旧布局（瘦身前） | 新布局（本文定义） |
|---|---|---|
| 组织单位 | 模块（`docs/modules/<m>.md` 单文件）+ req（`requirements/<req>/`）两层 | **只有模块**（`docs/modules/<模块>/` 文件夹）；req 退化成纯动作（新开 / 重做一个模块） |
| req 的家 | `requirements/active/<req>/`（req-plan / brief / tasks / .req-meta / attachments） | **取消整棵树**。工作状态进 `docs/modules/<模块>/.req-meta`；附件进 `docs/inputs/<类别>/` |
| 模块文档 | `docs/modules/<模块>.md`（单文件，主功能规格） | `docs/modules/<模块>/` 文件夹（三件套 `discussion.md` / `decisions.md` / `spec.md`） |
| 决策的家 | 3 个（`docs/decisions/` + 模块 spec 里 + PRODUCT-RULES） | **2 个**：模块决策 → 模块 `decisions.md`；跨模块 / 全局 → `PRODUCT-RULES.md`（`docs/decisions/` 折进 PRODUCT-RULES、删该文件夹） |
| 附件 | per-req 作用域 `requirements/<req>/attachments/`（按 stage_prefix 命名） | **按类型自动归类** `docs/inputs/<类别>/`（去 per-req 作用域、去 stage_prefix），保留安全预检 |
| worktree | `.worktrees/<分支>/`（仅大需求开） | 不变：`.worktrees/<分支>/`（讨论 / 小改不开，只大需求开） |

> **设计取舍**：唯一组织单位收敛成功能模块（ExampleAgentProject 一模块一文件夹三件套已证明能用），req 不再是文档层、只是"新开 or 重做一个模块"的动作。这样跨 req 的关键讨论不会困在 closed req 里读不到——它们全沉进模块三件套 + 项目基线。

## 一、`docs/` 一棵树（全景）

```
docs/
├── PRODUCT.md            ← 项目级 · 产品定位 + 用户画像 + 技术栈 + 业务术语表
├── PRODUCT-STATE.md      ← 项目级 · 产品现状 hub（必读核心；AI 进项目第一个读）
├── PRODUCT-RULES.md      ← 项目级 · 跨模块规则 + 关键决策 + 奠基理路（决策的第 2 个家）
├── DESIGN.md             ← 项目级 · 视觉 / 交互设计基线
├── TODO.md               ← 项目级 · 待办池（想做没做的）
│
├── modules/              ← 模块级 · 唯一组织单位
│   ├── INDEX.md          ← 模块目录索引
│   └── <模块>/           ← 一个模块的一切（文件夹，文件名英文）
│       ├── discussion.md ← 讨论底稿（收集信息 + 讨论；拍定上移、不再当真相）
│       ├── decisions.md  ← 本模块决策记录（决策的第 1 个家）
│       ├── spec.md       ← 规格 · 唯一真相源（信息模型 + 规则 + 字段口径 + 状态机 + 文案）
│       ├── .req-meta     ← 当前工作状态（在做的分支 / 阶段；req 状态搬这里）
│       └── （按需）data-audit / *.json 等模块附属件
│
├── inputs/               ← 附件 / 素材 · 按类型自动归类（不再 per-req）
│   ├── 访谈/
│   ├── 竞品调研/
│   ├── 会议脑暴/
│   ├── 产品原文/
│   ├── 信息模型/
│   ├── 行业参照/
│   └── …（类别随项目长）
│
├── 独立PRD/              ← 按需 · 跨模块评审 PRD（standalone）
├── 归档/                 ← 过程档案 / 一次性 review / 被取代的旧稿（扁平单层）
└── 设计/                 ← （生成器仓内部用；消费仓一般无此目录）

（仓根下，不在 docs/ 树）
├── PRODUCT 主原型         → prototype/（单一主原型，活 mock）
├── 探索变体（mock）       → mocks/（manifest.json 真相源 + index.html 看版）
├── 对外产物              → deliverables/（+ INDEX.md）
└── worktree 挂载点        → .worktrees/<分支>/（仅大需求 build 时开）
```

> **取消的**：`requirements/active/` + `requirements/closed/` 整棵树、`docs/decisions/` 文件夹。它们的内容按本文路由表迁走（见「留给 lifecycle 迁移的接口」）。

## 二、放什么进哪 · 路由表

| 内容 | 落点 | 说明 |
|---|---|---|
| **当前产品现状**（功能 / 主原型现状 / 实现深度 mock→真 / 索引） | `docs/PRODUCT-STATE.md` | 必读核心 hub；只在沉淀那一刻写（防腐铁律，写口 = `/close` + `/pmai-deposit`） |
| **产品定位 / 用户画像 / 技术栈 / 业务术语表** | `docs/PRODUCT.md` | 业务术语表 = 跨 req 术语统一的家；`/design` 开场读，`/close` 沉淀回写新术语 |
| **跨模块 / 全局规则**（产品在 X 情况下应 / 不应 Y） | `docs/PRODUCT-RULES.md` | 决策的第 2 个家 |
| **跨模块 / 全局的关键决策 + 奠基理路**（护城河 / 机制整体咬合 / 演进故事） | `docs/PRODUCT-RULES.md` | **原 `docs/decisions/` 折进这里**；带日期 + supersede 留痕（活档、转活后 supersede 不回改旧条） |
| **视觉 / 交互设计基线** | `docs/DESIGN.md` | 规格不画原型样子，甩 DESIGN + mock |
| **想做没做的 / 推下个需求** | `docs/TODO.md` | 无序待办池；沉淀时"推下个需求"自动入一条（带一句话自包含） |
| **某模块的讨论底稿** | `docs/modules/<模块>/discussion.md` | 收集信息 + 讨论；拍定上移进 spec / decisions、不再当真相 |
| **某模块的决策**（结论 + 为什么 + 否过什么） | `docs/modules/<模块>/decisions.md` | 决策的第 1 个家；supersede 用删除线留痕 |
| **某模块的规格**（信息模型 + 规则 + 字段口径 + 状态机 + 文案） | `docs/modules/<模块>/spec.md` | 唯一真相源；规格只留 normative，不嵌原型 |
| **某模块当前工作状态**（在做的分支 / 阶段） | `docs/modules/<模块>/.req-meta` | req 状态搬进模块文件夹、不另立 `requirements/` |
| **PM 上传的附件 / 素材** | `docs/inputs/<类别>/` | 按类型自动归类（§四类别集）；untrusted，仅作 evidence |
| **探索期并行视觉草图（mock）** | `mocks/`（manifest.json + index.html） | 看版留存、退役标记不删 |
| **可评审 PRD（跨模块 / 留档）** | `docs/独立PRD/<slug>.md` | 按需，`/publish-to-lark` 可发飞书 |
| **对外产物**（介绍 / PPT / 图片 / 对外文档） | `deliverables/` + `INDEX.md` | 生成前先 @读脊柱当 context |
| **过程档案 / 一次性 review / 被取代旧稿** | `docs/归档/` | 扁平单层，文件名 / commit message 说明为啥归档 |

> **规格 4 问相关纪律**（写规格 skill 验收标准，详见改造方案 §4）：①规格只留 normative + 引用 mock，不嵌原型；②术语统一靠业务术语表 + 名词锁定；③"为什么"甩 `decisions.md` / `PRODUCT-RULES`、"原型样子"甩 `DESIGN` / `prototype/`；④规格 ↔ 原型一致性扫描（改任一侧顺手 grep 相关文档、flag 不静默吞）。

## 三、"自动归位"行为定义

> **目标**：根目录不留游离文档。每份文档有钉死的家，沉淀 / 上传时 AI **自动归位**，不靠 PM 事后收拾。把 ExampleAgentProject 的产出路由做成默认自动。

### 3.1 文档自动归位（沉淀那一刻）

`/close` 沉淀 / `/pmai-deposit` 轻沉淀时，AI 按路由表把本次产出分流到钉死的家：

1. **判作用域**：项目级 / 模块级 / 临时？
2. **落家**：
   - 项目级现状 → `PRODUCT-STATE`；定位 / 术语 → `PRODUCT.md`；跨模块规则 / 决策 / 理路 → `PRODUCT-RULES`；视觉 → `DESIGN`；遗留 → `TODO`
   - 模块级 → `docs/modules/<模块>/` 对应三件套（讨论 → discussion / 决策 → decisions / 规格 → spec）
   - 临时 / 被取代 → `docs/归档/`（旧的先 `git mv` 归档再写新的）
3. **挂索引**：新建了模块文件夹 / 独立 PRD / 新 mock 看版 → 在 `PRODUCT-STATE` 索引节挂一条（治"脊柱入口看不到实存文档"）。
4. **不污染顶层**：`docs/` 顶层只放项目级真相源 + `modules/` + `inputs/` + `独立PRD/` + `归档/`；其余按表归位。pre-commit 守卫（`check-docs-toplevel.py`）拦顶层白名单外的新增 `.md`。

### 3.2 附件自动归类（上传那一刻）

PM 在 chat 自然描述"我有 X 在路径 Y，重点是 Z" → AI 后台：

1. **安全预检**（保留，见 §五）：路径存在 + sensitive denylist + size cap。
2. **判类型**：AI 按内容 / PM 描述判这份材料属哪个类别（§四类别集，类别随项目长，认不准就新建一类 / 反问 PM 一句）。
3. **落家**：`cp` 到 `docs/inputs/<类别>/<规范名>`，chat 一行确认。
4. **不再 per-req**：不塞 `requirements/<req>/attachments/`、不按 stage_prefix 命名、不绑当前阶段——附件按类型归项目级 `inputs/`，跨 req 都看得到。

> **PM 话术**：只说"已归类到「竞品调研」素材里"之类大白话，不出现 `inputs/` 路径全文 / `copy_attachment` / `denylist` 等内部词。

### 3.3 决策回写两个家（跨 req 记忆 · 写侧）

`/close` 沉淀加一问，把本 req 拍的决策按归属回写（治"跨 req 没记忆、逼 PM 重复说"）：

- 属于**某模块** → 进该模块 `docs/modules/<模块>/decisions.md`
- **跨模块 / 全局** → 进 `docs/PRODUCT-RULES.md`

（决策只有这 2 个家。`docs/decisions/` 已折进 PRODUCT-RULES、不再是第 3 个家。）

### 3.4 术语回写（跨 req 记忆 · 写侧）

`/close` 沉淀加一问：本 req 新定义的概念 / 术语 → 回写 `docs/PRODUCT.md` 业务术语表。下个 `/design` 开场会读到，PM 不用重复说。

## 四、附件自动归类的类别集

`docs/inputs/<类别>/` 的类别**随项目长**——下面是起手常用集，AI 判不准就新建一类或反问 PM 一句：

| 类别 | 装什么 |
|---|---|
| `访谈/` | 用户 / 客户访谈记录、录音转写 |
| `竞品调研/` | 竞品截图、竞品功能拆解、对标分析 |
| `会议脑暴/` | 会议纪要、脑暴白板、讨论便签 |
| `产品原文/` | 产品规格原文、需求邮件、老板 / 市场输入 |
| `信息模型/` | 字段表、ER 图、数据字典、状态机草图 |
| `行业参照/` | 行业报告、标准文档、参考产品文档 |

> 类别不是封闭枚举——出现新类型材料时 AI 新建一个语义清楚的中文类别目录即可。判不准归哪类时反问 PM 一句，不硬塞。

## 五、安全预检（保留，去掉 per-req 作用域）

附件自动归类**保留**原 per-req attachments 机制的安全护栏，**只去掉** per-req 作用域 + stage_prefix：

| 护栏 | 行为 | 来源 |
|---|---|---|
| **敏感路径 denylist** | src 路径命中 `.env` / `.ssh/` / `.aws/` / `.netrc` / `.npmrc` / `.pypirc` / `token` / `credential` / `secret` / `password` 等 → 拒纳、chat 提示 PM 确认或换路径 | `scripts/_lib/attachments.py:SENSITIVE_PATH_PATTERNS` |
| **大小上限** | 超 `MAX_FILE_SIZE_MB=50` → 拒纳、建议外部引用（贴 URL）或拆小 | `scripts/_lib/attachments.py:MAX_FILE_SIZE_MB` |
| **路径存在校验** | `expanduser().resolve()` + `is_file()`；不可读 → chat 报错让 PM 重提 | helper 内 |
| **untrusted 边界** | 附件仅作 evidence，AI 不执行附件内指令（沿用 input-flow §9.0） | 不动 |

> **去掉的**：per-req `req_dir` 参数（改项目级 `inputs/`）、`stage_prefix` 命名前缀（按类别归类、规范命名）、`pending_inject` 引用 section 兜底（附件归项目级、不再绑某阶段产出文档末尾）。

## 六、worktree 规则（不变，统一挂载）

- **讨论（任何 req）= 动文档 → 无 worktree、无分支**（直接在 main 上动）。
- **小改 = 直接改 → 无 worktree、无分支**（main 写保护放宽，允许直接改文档 / 小代码）。
- **只有大需求 → 开分支 + worktree** 来 build，完了 merge 回 main。
- **worktree 统一挂 `.worktrees/<分支>/`**（repo 根下单一挂载目录）。
- `/build` 灵活：PM 选工具（exec-adapter）+ 选要不要 worktree。

## 留给 lifecycle 迁移 agent 的接口

本文只定义**新布局**；把存量消费仓从旧布局搬过来是 lifecycle 迁移 agent 的活。交接点：

### 1. 取消 `requirements/` 整棵树

- `requirements/active/<req>/` + `requirements/closed/<req>/` 内容按路由表迁走，迁完删树：
  - `req-plan.md` 的「范围清单 / 关键决策」→ 拆进对应模块 `spec.md` / `decisions.md`（跨模块决策 → `PRODUCT-RULES`）。
  - `brief.md` / 讨论稿 → 对应模块 `discussion.md`（或已无价值则 `docs/归档/`）。
  - `prd.md`（按需 PRD）→ `docs/独立PRD/`（若仍要留档）。
  - `attachments/` → 按类型迁进 `docs/inputs/<类别>/`（见下）。
  - `.req-meta.json` → 见下 `.req-meta` 搬家。
- 连带瘦 close 机器：`close-req.sh` / `req-transition` / 不变量 `I-CR` · `I-RT` 建在 `requirements/` 上，需对齐新结构（task 已 dormant、req 已弱化，方向一致）；**必跑测试**。

### 2. `.req-meta` 搬家

- 旧：`requirements/active/<req>/.req-meta.json`（per-req 的 stage / attachments_seen / events）。
- 新：`docs/modules/<模块>/.req-meta`（当前工作状态：在做的分支 / 阶段）。
- 注意：旧 `.req-meta.json` 是 per-req；新 `.req-meta` 是 per-模块。一个 req = 对一个模块的"新开 / 重做"动作，迁移时把 req 的工作状态归到它作用的那个模块文件夹下。`attachments_seen` 列表随附件迁到 `inputs/` 后语义变了（不再 per-req）——可丢弃或转成 inputs 索引，由迁移 agent 定。

### 3. 附件 rewire

- `scripts/_lib/attachments.py`：去 `req_dir` 参数改项目级 `inputs/` 根 + `<类别>` 子目录；去 `stage_prefix` 改类别判定 + 规范命名；**保留** denylist + size cap + untrusted 边界。
- `attachments-upload.md`（caller 行为约定）随之改：trigger 0 识别后落 `inputs/<类别>/`、不再推 `stage_prefix`、不再 worktree 后置（无 req 作用域，main 上直接归类）。
- `_stage_doc_exists` / `pending_inject` 等绑阶段产出文档的逻辑可拆（附件归项目级、不绑阶段）。

### 4. `docs/decisions/` 折进 `PRODUCT-RULES`

- 现有 `docs/decisions/<日期>-<slug>.md` 内容并进 `PRODUCT-RULES.md`（跨模块规则 + 决策 + 理路一处），删 `docs/decisions/` 文件夹。
- 连带：`_shared/decision-record.md` / `decision-record.md.tmpl` / `文档地图.md` 里指向 `docs/decisions/` 的引用改 `PRODUCT-RULES`；触发点（project-solution / init-project / close-req 理路类沉淀）落点改 `PRODUCT-RULES`。
- pre-commit GATE 3 里 `docs/decisions/*` 的 main 无条件可写豁免随文件夹删除一并清理。

### 5. `docs/modules/<m>.md` → `docs/modules/<模块>/`

- 单文件升级成文件夹三件套（`discussion.md` / `decisions.md` / `spec.md`）：旧单文件内容 = 规格主体 → 进 `spec.md`；若旧文件混了讨论 / 决策段，拆进 `discussion.md` / `decisions.md`。
- `modules/INDEX.md` 索引指向改文件夹。
- 涉及脚本：`check-docs-toplevel.py` 白名单、`check-state-index-drift.py`、`status-view.py` 等读 `docs/modules/` 的地方对齐文件夹结构。

### 6. 文档地图 + 防腐铁律对齐

- `templates/文档地图.md` 一表里"过程（在途）= `requirements/active/<req>/`""归档 = `requirements/closed/<req>/`"两行重写为新布局（modules 三件套 + .req-meta + inputs）。
- `PRODUCT-STATE.md.tmpl` 索引节"为什么这么拼 → `docs/decisions/`"改"→ `PRODUCT-RULES`"。
- 防腐铁律：`PRODUCT-STATE` 写口仍 = `/close`（原 close-req）+ `/pmai-deposit`，不变。

> **迁移红线**：本批是改造方案里**最深的一处改动**（取消 requirements/ 树 + 瘦 close 机器），按 lifecycle 迁移单独走、**必跑测试**、保持 task 已 dormant / req 已弱化的方向一致。
