# design skill 反馈 · 2026-06-22

> **来源**：本轮用 `/pmai-design` 重做 ROI 模块时暴露的两个洞。
> ① AI 把 ROI 错当纯后端"引擎判定"、声明"非界面卡、三身份不涉及"，于是把呈现 / 交互设计整个跳过——一次没跟 PM 确认 ROI 卡怎么显示 / 放哪 / 怎么交互。规格只写了 ROI 判什么 / 输出什么，没写 HOW/WHERE 呈现。
> ② 前几轮在老 ROI 公式上反复打补丁（早期粗档粗规则 → 又硬塞跟进周期 / 置信度 / 风险盯防），被 PM 推了好几次（"判档不太行""你看京国瑞""置信度的意义""信息不全的信号本来就有"）才回根因推倒重来。

## 消化结果对账表

| # | 反馈 | 落地状态 | 落地位置 | 说明 |
|---|---|---|---|---|
| 洞1 | **分类本身有问题**：七类把"后端怎么算"和"给人看怎么呈现"混在一张"选一个"的清单里，引擎判定顺手就把呈现面丢了 | ✅ 已落地（重构） | `_shared/info-design.md` §二 + `design/SKILL.md` 段② / Rules | 把分类拆成**正交两面**：逻辑面（后端规则 / 算法 / 引擎 / 流程）+ 呈现面（信息密集 UI 卡 / 管理页 / 数据产物）。先判逻辑面、再判**有没有呈现面**；**结果给人看 → 呈现面必做**（落点 / 卡面 / 抽屉 / 交互[看依据·否决·过目] / 待办落点）+ PM 确认 + 视觉调 /mock，别把引擎判定只当后端就收工。加段②**收尾自检**：有用户看得见的输出？确认过显示在哪 / 怎么交互了吗？没确认不进写规格。 |
| 洞2 | **根因优先靠自觉、且依赖全局 CLAUDE.md**；该让 skill 自带、更难漏 | ✅ 已落地 | `design/SKILL.md` 铁律「根因优先」 | 改成 **skill 自包含**（不依赖全局规则）+ 保留"**第一次就停**"严度 + 加"**打补丁自检信号**"（发现自己在出修订版 / 加补字段·提示·输出块 = 在打补丁，停下回信息模型）。 |

**未采纳**：AI 原提案的"补丁计数器（同一处否两次→第三次才停）"——经对账发现它比现有"第一次'不对'就停"**更松、方向反了**，PM 否，改为强化现有规则 + 自检信号。
