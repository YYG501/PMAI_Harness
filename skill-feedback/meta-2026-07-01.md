# /pmai-meta v2 反馈消化记录

## 原始反馈摘要

PM 反馈 2026-06-30 的 `/pmai-meta` 改造仍然不够好：模型看起来只是换了说法，没有真正吸收 gstack office-hours 和 grillme 的设计。真实失败样例是：AI 在讨论 `lark-doc-edit / pmai-lark-sync / publish-to-lark` 这类 PMAI workflow 问题时，没有先读现有 skill 边界，就建议新建 skill；给 alternatives 后没有硬停顿，继续收束和路由；最后还把 skill / workflow 改造引到 `/pmai-design`，逻辑混乱。

PM 后续补充：此前用 gstack office-hours 沉淀产品想法效果不错，所以不能简单判断为“不适用”。更准确的判断是：gstack office-hours 对“产品想法孵化”有效，但 PMAI 不能把它作为黑盒运行时托管；PMAI 还需要自己的 workflow / skill 决策路径，以保护真相源、skill 边界、测试和下游落点。

## 参考来源

- gstack office-hours：产品想法沉淀时，先确认目标和模式，再围绕现状对手、需求证据、最小切口和失败预演推进；关键不是“问很多问题”，而是 gate 和 stop。
- gstack office-hours 测试：把 AskUserQuestion 被跳过、Phase 4 alternatives 后没停住、问题力度变弱写成回归测试。
- Matt Pocock `/grill-me` / `/grilling`：用户入口很薄，核心是可复用的访谈纪律：沿决策树逐个 resolve、一题一问、每题给推荐答案、能从代码查到就不问用户。
- Matt Pocock `/grill-with-docs` / `/domain-modeling`：访谈和领域语言沉淀分层，避免把所有职责塞进一个厚入口。

## 采纳决策

- 保留 `/pmai-meta` 命令名，不新增公开 `/pmai-office-hours`。
- 不把 gstack 或 mattpocock skills 作为运行时依赖，也不 vendoring 社区 skill。
- `/pmai-meta` 定位为 PMAI 问题会诊入口，不再是单一路径的“问题对焦”文档。
- 产品想法会诊吸收 gstack office-hours 的有效方法。
- PMAI workflow / skill 决策走 PMAI 自己的真相源、skill 边界和下游落点。
- 旧 meta 的升维、第一性原理、多视角压测和 UI 三层问法继续保留在 thinking toolbox。
- 用测试锁失败模式，不再只靠文档说明约束模型。
