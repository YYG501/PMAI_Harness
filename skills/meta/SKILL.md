# /pmai-meta · 对焦与压力测试

> **它是什么**：一个讨论前的"重新看问题"入口。在回答"这个怎么做/怎么写/要不要继续"之前，先判断现在需要**对焦**、**推导**，还是对一个已有对象做**多视角压力测试**。
> **它不做什么**：不替你写稿、不替你做完整设计、不替你拍板、不把话说虚。产出型工作继续交给 `/pmai-design`、`/pmai-prd-writing`、`/pmai-doc-writing`、`/pmai-build`。
> **金标准**：讨论完，PM 不仅知道"这个问题应该怎么看 / 哪些盲区最危险"，还拿到了**页面上、方案里、文档中或下一步具体该改什么**。

---

## 入口判断：先看有没有锚点

**锚点** = 一个可被分析的对象，例如一份稿子、一个方案、一个页面设计、一个规格草案、一个方向判断、一个候选结论，或一段准备继续往下走的材料。

| PM 的真实诉求 | 有没有锚点 | 走哪种动作 |
|---|---:|---|
| "这事到底该怎么看 / 本质是什么 / 该按什么标准判断" | 可无 | **对焦**：升维，找判断标准 |
| "这个前提成立吗 / 为什么必须这样 / 别按惯例想" | 可无 | **推导**：第一性原理，拆约束和假设 |
| "这份稿子 / 方案 / 判断帮我多角度挑一下" | 有 | **压测**：少量多 AI 视角找盲区 |
| "我感觉不对，但说不上来" | 先判断 | 没锚点先对焦；有明确对象再压测 |

没有锚点时，不要硬开多个 agent；先把靶子立对。有锚点但压测发现靶子本身错了，就停止继续列问题，回到对焦。

---

## 三个动作，一个共同的敌人

| 动作 | 方向 | 干什么 | 治什么病 |
|---|---|---|---|
| **对焦 / 升维** ↑ | 往上 | 把一个具体设计放进更高的"判断标准"：它改变谁的判断？动了哪个更高标准？ | 停在"我有什么功能"，定位/文案/优先级讲得像产品介绍 |
| **推导 / 第一性原理** ↓ | 往下 | 拆到不可再拆的基本事实，质疑每个"大家都这么做"，从地基重新推导 | 靠类比和惯例做决定 |
| **压测 / 多视角** ↔ | 多侧 | 对已有锚点生成少量互补视角，找盲区、冲突、硬伤和根因 | 自己看不出病灶，或单一视角容易漏 |

共同的敌人都是**停在表面**：表面的功能、表面的类比、表面的黑话、表面的"多 agent"热闹。
共同的收尾都是**降回设计**：升维找到的"判断"、第一性原理推出的"结论"，最后都要变成具体的页面/方案动作。

这三个动作可以串联，但不要仪式化：没有靶子先对焦，有靶子再压测；压测发现靶子错了，回对焦。

---

## 第一步：闸门——这个问题要不要进 meta？

**不是所有问题都要进 meta。强行深想只会变空话。** 先判断：

**直接做，不进 meta**（满足任一）：
- 纯执行细节：按钮放左还是右、字段叫"状态"还是"阶段"、图标什么颜色 → 回到可用性、认知负担、视觉层级。
- 技术实现正确性：接口怎么设计、表怎么建、权限怎么实现 → 先把工程做对。（**例外**：做架构/方案取舍时可以钻第一性原理——"这个模型未来能不能撑多产品接入"。）
- 已经很明确的小需求：润色一句话、改个表格描述、写段提示语 → 直接做。（**例外**：这句话承担了定位/传播/定价/管理判断时，才升维。）

**值得进 meta**（命中任一即可）：它会影响 → 用户判断 / 管理决策 / 资源分配 / 成本投入 / 风险控制 / 收入质量 / 利润结果 / 组织能力 / 少掉的焦虑 / 能不能坚持 / 维护成本 / 出错概率 / 可逆性 / 机会成本 / 市场认知 / 产品定位；或 PM 明确想找盲区、多视角、反方、几个 agent 分别看。

> 闸门没过就别硬上。该直接做的就直接做，并一句话说明"这个不用想太多，直接做更对"。

---

## 第二步：选动作（对焦 / 推导 / 压测）

- 问题是 **"这东西到底算什么 / 该按什么标准取舍 / 该怎么定位、怎么说"** → **升维**为主。
- 问题是 **"为什么要这样 / 这个前提成立吗 / 大家都这么做对吗"** → **第一性原理**为主。
- 问题是 **"这份稿子 / 这个方案 / 这个判断从多个角度看有什么盲区"** → **多视角压力测试**为主。
- 重大定位、产品思路、架构选择 → **两个都用**：先第一性原理拆出地基事实，再升维找地基所服务的最高判断。

不确定时先对焦，不要先开 agent。agent 是为了减少盲区，不是为了制造声量。

## 动作 A · 对焦 / 升维 ↑

### A0. 先认这轮讨论在判断什么（决定往哪升）

升维的**本质**是把一个具体方案放进一个**更高的判断标准**重新衡量。**"更高的标准"是什么，取决于这轮讨论到底在判断什么——不是写死成"企业经营账本"，也不是先按对象机械分类。** 先认清当前卡点，再选最能解释这个卡点的标准：

| 这轮真正要判断的是 | 往哪升（更高的判断标准） |
|---|---|
| 企业 / 组织为什么要用、要不要投、值不值得继续做 | **经营账本**：收入/成本/利润/风险/资源/时间/组织能力（账表见 A2） |
| 个人为什么要用、用完生活哪里变好 | **人生账本**：省不省时间、少不少焦虑、能不能变好、值不值得花这精力 |
| 工具为什么值得进工作流、长期用会不会拖累人 | **工程账本**：可维护性、认知负担、出错概率、未来扩展成本 |
| 做不做、A 还是 B、先做哪个 | **目标账本**：它推进哪个真正目标、代价、机会成本、可逆性 |
| 一句话 / 命名 / 定位想让人怎么理解 | **认知账本**：它让谁形成什么印象、改变谁的心智坐标 |

同一个对象在不同讨论里可以升到不同标准。比如同一个企业 SaaS：讨论优先级时可能看经营账本；讨论一句定位怎么写时可能看认知账本；如果那句定位空洞，再回到真实经营价值找支撑。**不要把对象类型当成唯一答案，也不要先替几个标准排主次。**

认不清这轮在判断什么 → 先问 PM "这次我们到底是在判断要不要做、给谁用、怎么说，还是页面该服务哪个判断"，别瞎套账本。**硬把个人使用问题套"售前投入/资源错配"就是硬凹，立刻停。**

### A1. 先定位：现在停在哪层（用上一步选的标准）

各类都有自己的"低→高"阶梯。**经营判断**的企业产品阶梯（最常用，作主例）：

| 层级 | 关注 | 质感 |
|---|---|---|
| 功能层 | 它能做什么 | 普通，像产品介绍 |
| 场景层 | 谁在什么场景用 | 还行 |
| 管理层 | 它改变了什么流程/决策 | 稳 |
| 经营层 | 它如何影响收入/成本/利润/风险 | 高级 |
| 战略层 | 它如何改变企业竞争方式 | 更高 |
| 时代层 | 它代表什么趋势 | 媒体感最强 |

其他类用同构的"低→高"：消费者产品 = 功能 → 场景 → 习惯养成 → 人生质量；工具 = 功能 → 顺手 → 可维护 → 长期工程成本；取舍 = 选项 → 目标 → 代价 / 可逆性；文案 = 信息 → 印象 → 心智坐标 → 行动 / 转述。先诚实说"现在停在哪层"——大多停在功能/场景层。升维就是从低层跳到高层。

### A2. 问这 5 个问题（逐个答，不要跳）

1. **它表面上在做什么？**（功能层的诚实描述）
2. **它真正改变了谁的判断？**（不是"帮 X 提效"，而是"帮 X 判断该不该/选哪个/投不投"——用 A0 选定标准里的判断主体）
3. **放进更高的标准看，它动了什么？** ← 最关键。经营账本就是动哪张账（见下表）；人生账本就是动了时间、焦虑、习惯还是成长；工程账本就是动了维护成本、认知负担还是出错概率；目标账本就是动了目标、代价还是可逆性；认知账本就是动了第一眼印象、心智坐标还是转述能力。**必须落到那类的具体标准，不空说。**
4. **它把什么从 A 变成了 B？**（用"从…到…"句式，见 references）
5. **它反对什么旧范式？**（找到它跟什么作对，表达才锋利）

**经营账本**（经营判断时第 3 问的选项；其他标准用对应账本）：

| 账 | 高级表达落点 |
|---|---|
| 收入账 | 是否带来更多高质量收入 |
| 成本账 | 是否减少无效售前/交付/研发投入 |
| 利润账 | 是否让每一单更赚钱 |
| 风险账 | 是否提前识别不值得做的事 |
| 资源账 | 是否让有限资源投向更确定的机会 |
| 时间账 | 是否缩短从线索到结果的路径 |
| 组织账 | 是否让经验从个人能力变成组织能力 |

### A3. 措辞纪律

升维结论**必须落到 A0 选中标准的具体判断词**——经营判断落到经营词（损益表/毛利/现金流/风险敞口/机会成本…），个人使用价值落到人生账本词（省的时间/少掉的焦虑/能不能坚持…），工具长期使用落到工程账本词（维护成本/出错概率/扩展代价…），取舍判断落到目标账本词（真正目标/机会成本/可逆性…），表达理解落到认知账本词（第一眼印象/能否转述/心智坐标…）。**禁用黑话**（重构/赋能/闭环/智能化…），也**禁用错域的词**（给个人使用问题硬塞"售前投入/资源错配"）。完整禁用词表、各域判断标准词库、从 A 到 B / 旧范式表达校验 → 见 `references/词表与句式.md`。

## 动作 B · 推导 / 第一性原理 ↓

往下钻，把问题拆到地基，重新长出答案。四步：

1. **拆到基本事实**：把这个东西拆成不能再拆的几条事实。问"哪些是真的物理/经济/人性约束，哪些只是惯例和类比？" 区分**约束**（真拆不掉）和**假设**（其实可改）。
2. **质疑每个假设**：对每条非约束的东西问"为什么是这样？谁规定的？如果不这样会怎样？" 大多数"必须这样"经不起追问。
3. **从地基重新推导**：只用第 1 步留下的真约束，重新推一遍这个东西"应该长什么样"。不许引用"竞品都这么做""我们一直这样"。
4. **对比现状，看差在哪**：重推的结论和现在的方案差在哪？差异处就是机会或问题所在。

**判断一条是"约束"还是"假设"**：约束 = 改了它整件事就不成立（用户一天只有 24 小时、钱要回款才是钱、人记不住超过 7 个东西）。假设 = 改了它只是"不习惯"（这个一直放侧栏、报价要先走审批、CRM 就该按客户组织）。**把假设当约束，是绝大多数平庸方案的根因。**

> 第一性原理的产物不是"颠覆一切"，而是**几条被验过的地基事实 + 一个不靠惯例支撑的结论**。

## 动作 C · 多视角压力测试 ↔

用于已有锚点时：一份稿子、一个方案、一个页面设计、一个规格草案、一个方向判断、一个候选结论。目标是用少量互补视角找盲区，而不是多 agent 投票。

### C0. Agent 数护栏

| 场景 | 视角 / agent 数 |
|---|---:|
| 材料短、问题轻 | 2-3 个视角，可由主控直接分析，不必派 subagent |
| 单份文档 / 方案 / 文案，需要多角度挑刺 | 3-5 个，默认上限 5 |
| 多文件、多真相源、历史决策或高风险判断 | 4-6 个 |
| 产品方向、战略取舍、审美判断、争议大 | 5-7 个 |
| 超过 7 个 | 禁止默认启用；只有 PM 明确要求且每个视角不可合并时才允许 |

每个视角必须同时满足：

1. 它看的是一个独立问题，不是换名字重复别的视角。
2. 它有自己的判断标准。
3. 如果不跑它，确实可能漏掉一种重要风险。

不满足就合并或删除。**视角要够互补，不要够多。**

### C1. 生成视角

不要套固定模板；根据锚点和 PM 目标生成 2-7 个视角。候选库只用于启发：

| 视角类型 | 适合看什么 |
|---|---|
| 约束 / 真相源 | 是否违反硬边界、既有决策、规格原文、业务规则 |
| 用户 / 读者 | 目标用户是否看得懂、信不信、会不会行动 |
| 业务目标 | 是否服务真正目标，是否只是功能堆叠 |
| 产品逻辑 | 用户路径、对象关系、状态变化、优先级是否成立 |
| 证据 | 结论有没有来源，哪些只是推断 |
| 表达质量 | 是否绕、空、假、大、AI 腔、口径不稳 |
| 信息结构 | 层级、顺序、每段承担的问题是否清楚 |
| 完整性 | 关键角色、场景、异常、边界、后续项是否漏掉 |
| 可执行性 | 下一步能不能落地，是否缺输入、缺验收标准 |
| 风险 | 法务、承诺、成本、资源、误导、不可逆风险 |
| 反方 | 专门论证"为什么这套东西可能不成立" |
| 质感 / 审美 | 是否刻意、低级、堆砌、像模板；这类软判断不能被 P0/P1/P2 框死 |

压缩规则：

- 同一判断标准的视角合并。
- 只看措辞的小视角并入表达质量。
- 只看证据的小视角并入真相源 / 证据。
- 反方只在解释空间大时启用；事实对照类任务优先查证据，不默认辩论。

### C2. 派发独立分析

runtime 有 subagent / multi-agent 能力时，按视角并行派发。没有时，明确说明"本轮按单主控多视角退化执行"，不要假装跑过独立 agent。

每个 subagent 的任务必须窄：

```text
你只负责【视角名】。
分析对象：【文件 / 内容 / 问题】
判断标准：【本视角怎么判好坏】
只读，不改文件。
不要替其它视角下结论。
最多返回 5 条 finding，P0/P1 优先；P2 最多 2 条。
没有关键问题就说"本视角未发现关键问题"，不要硬凑。

返回结构：
视角：
判断标准：
总体判断：
关键发现：
- 位置 / 证据：
- 严重度：
- 问题：
- 为什么重要：
- 改法方向：
不确定项：
本视角没覆盖的范围：
```

严重度口径：

- **P0**：违反硬约束、事实错误、包赢式承诺、方向性错误，会导致材料不能继续用。
- **P1**：主要目标受损、关键误导、结构断裂、重要缺口，应优先修。
- **P2**：局部优化、表达问题、可读性或完整性小缺口。
- **软判断**：高级感、刻意感、信任感、审美判断等，不强行塞进 P0/P1/P2；单列说明。

### C3. 主控合成

主控不要拼接 agent 摘要，要做合成：

1. **去重**：同一问题只保留最强证据。
2. **升降级**：按证据和风险重判严重度，不照搬 agent。
3. **找冲突**：视角之间结论不一致时，说明冲突点和主控判断。
4. **找根因**：多个症状是否来自同一个底层问题。PM 质疑"不合理 / 感觉不对"时，先回根因和最直接解法。
5. **保留无问题确认**：事实对照类任务里，对得上的内容要列出"其实没问题"，避免只为了挑刺制造漂移叙事。
6. **收敛数量**：最终"关键问题"默认最多 7 条，"最该先改"最多 3 条；其它放备查。

### C4. 压测输出

```text
## 总判断
这个锚点当前能不能继续往下走？最大问题是什么？

## 多视角结论
| 视角 | 判断 | 最重要的问题 | 严重度 |
|---|---|---|---|

## 最该先处理的 3 件事
1. [P0/P1/P2] 问题标题
   证据：
   影响：
   改法方向：

## 关键问题
（最多 7 条，去重后按严重度排序）

## 视角冲突
哪些视角结论互相冲突？主控怎么判？

## 根因
这些问题背后是不是同一个原因？如果是，根因是什么？

## 下一步
先改什么、先验证什么、哪些需要 PM 拍板。

## 局限
本轮没读什么、哪些判断不该装成事实。
```

根据 PM 诉求调整：只挑毛病就压缩总判断；要定稿就强化 P0/P1；要对齐规格就每条 finding 带 truth source 原文、路径和行号；要改法只给方向，不直接整篇重写。

---

## 第三步：降回设计（铁律，三个动作都要做）

升上去/钻下去**只是中途**。必须回到落地，否则全是空话。

- **升维之后** → 回答：这个判断意味着页面上/方案里该出现什么、强调什么、隐藏什么、默认什么？
  - 例：页面定位从"销售看任务"升到"负责人判断这单值不值得投" → 中心就不该是聊天框，而是"证据状态 + ROI 判断 + 下一步缺口"，默认筛选改成"高风险高金额商机"。
- **第一性原理之后** → 回答：基于重推的地基结论，现状哪里要改？第一步动什么？
- **多视角压测之后** → 回答：哪些问题必须先修、哪些只是备查、哪些需要 PM 拍板？如果靶子错了，停止修细节，回到对焦。

**一句话纪律**：高层用对应判断标准词 / 地基事实定方向，底层用交互细节、具体取舍和优先修正项落地。只升不降、只拆不建、只压测不收敛，都判不合格。

---

## 产品 UI 专用：3 层固定 + 高层按 A0 替换

讨论某个页面/组件时，先过 3 个固定层，再按 A0 选择更高标准（这是升维在 UI 上的具体形态）：

| 层 | 问什么 |
|---|---|
| 信息层 | 页面上到底展示哪些信息？ |
| 任务层 | 用户来这里要完成什么动作？ |
| 判断层 | 用户要基于这些信息做什么判断？ |
| 更高标准层 | 按 A0 替换：经营判断问管理/经营影响；个人使用价值问时间/焦虑/习惯；工具长期使用问认知负担/出错概率/维护成本；取舍判断问目标/代价/可逆性；表达理解问第一眼印象/能否转述。 |

低级问法"左边放什么右边放什么卡片怎么排"，会让信息乱堆。先问到判断层及以上，**再**反推信息、主操作、布局、以及"不该出现的东西"。B2B 工作台可以继续问管理/经营层；非企业产品不要硬套经营层。

## 输出格式：脑子里走流程，嘴上说大白话

**闸门 / 升维 / 第一性原理 / 五问 / 更高标准 / 哪张账 / 多视角 / 降回设计——这些是你脑子里走的流程，不是给 PM 的章节标题。** 对 PM 说话**不滥用这些方法论词**（PM 不关心你内部走了什么流程）。只有 PM 明确要"多角度挑 / 找盲区 / 几个 agent 分别看"时，才可以把视角和 finding 作为输出结构。

**对焦 / 推导时，对 PM 只输出两样，顺序固定**：

1. **一句重定位结论**：大白话，说清"这东西真正帮谁做什么决策 / 它的地基其实是什么"。落到 A0 选中的具体判断标准词（经营判断才用现金流 / 毛利 / 风险敞口；个人使用价值用省下的时间 / 少掉的焦虑 / 能不能坚持；工具长期使用用维护成本 / 出错概率 / 扩展代价；取舍判断用目标 / 机会成本 / 可逆性；表达理解用第一眼印象 / 能否转述 / 心智坐标），**禁方法论词**（升维 / 第一性原理 / 闸门 / 哪张账 / 换高度）**和黑话**（重构 / 赋能 / 闭环 / 智能化…）。
2. **具体落地**：页面上 / 方案里该出现什么、强调什么、隐藏什么、默认什么 / 第一步动什么。

**压测时，按 C4 输出**：先给总判断和最该先处理的 3 件事，再列关键问题、冲突、根因和局限。不要把每个 agent 的原始输出整段贴给 PM；PM 要的是合成后的判断，不是并行日志。

**闸门没过（不该拔高）** → 直接给答案 + 一句"这个不用想太多、直接做更对"，**不摆流程、不解释闸门**。

**PM 想看推导**（"你怎么想到的 / 展开讲讲 / 把过程写下来"）→ 才把五问、约束 vs 假设、从 A 到 B 的过程亮出来；这时可以用方法论词，因为 PM 主动要的是过程。**默认不亮。**

PM 要最终定位句 / 标题 / 对外表达时，本 skill 只输出重定位结论、判断标准和落地含义；成文与多方案表达交给 `/pmai-doc-writing`。

## 一句话

**不要问"这个东西怎么说得好听"，要问"它在更高层级上到底改变了什么"、"它的地基到底是什么、还成不成立"、"已有靶子从哪些互补角度会露出盲区"——然后降回去，决定页面上、方案里、文档中先改什么。**
