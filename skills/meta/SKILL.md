# /pmai-meta · 退一层看：升维 ↑ 第一性原理 ↓

> **它是什么**：一个讨论前的"对焦"动作。在回答"这个怎么做/怎么写"之前，先把讨论对象挪到对的高度——要么**往上升维**（放进更高的判断标准），要么**往下钻到第一性原理**（拆到地基重推）——看清楚了再落地。
> **它不做什么**：不替你做设计、不替你拍板、**不把话说虚**。升维不是"重构体验赋能增长"这种黑话，第一性原理不是"假装从零想其实还是原方案"。两者都有一条铁律：**升上去/钻下去之后必须降回设计**，否则就是空话。
> **金标准**：讨论完，PM 不仅听到"这东西在更高层改变了什么 / 它的地基是什么"，还拿到了**页面上/方案里具体该出现什么、强调什么、隐藏什么、默认什么**。

---

## 两个动作，一个共同的敌人

| 动作 | 方向 | 干什么 | 治什么病 |
|---|---|---|---|
| **升维** ↑ | 往上 | 把一个具体设计放进更高的"判断标准"：它改变谁的判断？影响哪张账？ | 停在"我有什么功能"，定位/文案/优先级讲得像产品介绍 |
| **第一性原理** ↓ | 往下 | 拆到不可再拆的基本事实，质疑每个"大家都这么做"，从地基重新推导 | 靠类比和惯例做决定（"竞品都这么做""一直都是这样"） |

共同的敌人都是**停在表面**：表面的功能、表面的类比、表面的黑话。
共同的收尾都是**降回设计**：升维找到的"判断"、第一性原理推出的"结论"，最后都要变成具体的页面/方案动作。

**两者还互相加固**：第一性原理给升维当地基——升维说"这影响利润账"，就用第一性原理验一遍"从基本事实推，这个利润真的成立吗"，防止升维变空话。

---

## 第一步：闸门——这个问题要不要换高度？

**不是所有问题都要升维/第一性原理。强行拔高只会变空话。** 先判断：

**直接做，不要拔高**（满足任一）：
- 纯执行细节：按钮放左还是右、字段叫"状态"还是"阶段"、图标什么颜色 → 回到可用性、认知负担、视觉层级。
- 技术实现正确性：接口怎么设计、表怎么建、权限怎么实现 → 先把工程做对。（**例外**：做架构/方案取舍时可以钻第一性原理——"这个模型未来能不能撑多产品接入"。）
- 已经很明确的小需求：润色一句话、改个表格描述、写段提示语 → 直接做。（**例外**：这句话承担了定位/传播/定价/管理判断时，才升维。）

**值得换高度**（命中任一即可）：它会影响 → 用户判断 / 管理决策 / 资源分配 / 成本投入 / 风险控制 / 收入质量 / 利润结果 / 组织能力 / 市场认知 / 产品定位。

> 闸门没过就别硬上。该直接做的就直接做，并一句话说明"这个不需要拔高，直接做更对"。

---

## 第二步：选动作（升维 ↑ / 第一性原理 ↓ / 两个都用）

- 问题是 **"这东西到底算什么 / 该怎么定位、怎么卖、怎么说"** → **升维**为主。
- 问题是 **"为什么要这样 / 这个前提成立吗 / 大家都这么做对吗"** → **第一性原理**为主。
- 重大定位、产品思路、架构选择 → **两个都用**：先第一性原理拆出地基事实，再升维找地基所服务的最高判断。

不确定就两个都跑一遍，成本很低。

## 动作 A · 升维 ↑

### A1. 先定位：现在在哪一层？

| 层级 | 关注 | 质感 |
|---|---|---|
| 功能层 | 它能做什么（自动生成方案、拆需求、算 ROI） | 普通，像产品介绍 |
| 场景层 | 谁在什么场景用（少走弯路、更高效） | 还行 |
| 管理层 | 它改变了什么流程/决策（资源不再靠感觉分配） | 稳 |
| 经营层 | 它如何影响收入/成本/利润/风险 | 高级 |
| 战略层 | 它如何改变企业竞争方式 | 更高 |
| 时代层 | 它代表什么趋势 | 媒体感最强 |

先诚实说出"现在停在哪层"——大多停在功能/场景层。升维就是从前三层跳到后三层。

### A2. 问这 5 个问题（逐个答，不要跳）

1. **它表面上在做什么？**（功能层的诚实描述）
2. **它真正改变了谁的决策？**（不是"帮 X 提效"，而是"帮 X 判断该不该/投到哪"）
3. **它影响企业哪张账？** ← 最关键，见下表，必须落到具体一两张。
4. **它把什么从 A 变成了 B？**（用"从…到…"句式，见 references）
5. **它反对什么旧范式？**（找到它跟什么作对，表达才锋利）

**哪张账**（第 3 问的选项）：

| 账 | 高级表达落点 |
|---|---|
| 收入账 | 是否带来更多高质量收入 |
| 成本账 | 是否减少无效售前/交付/研发投入 |
| 利润账 | 是否让每一单更赚钱 |
| 风险账 | 是否提前识别不值得做的事 |
| 资源账 | 是否让有限资源投向更确定的机会 |
| 时间账 | 是否缩短从线索到结果的路径 |
| 组织账 | 是否让经验从个人能力变成组织能力 |

### A3. 措辞纪律

升维结论**必须落到具体经营词**（损益表/毛利/现金流/风险敞口/机会成本…），**禁用黑话**（重构/赋能/闭环/智能化…）。完整禁用词表、经营词库、句式库、媒体标题生成 → 见 `references/词表与句式.md`。

## 动作 B · 第一性原理 ↓

往下钻，把问题拆到地基，重新长出答案。四步：

1. **拆到基本事实**：把这个东西拆成不能再拆的几条事实。问"哪些是真的物理/经济/人性约束，哪些只是惯例和类比？" 区分**约束**（真拆不掉）和**假设**（其实可改）。
2. **质疑每个假设**：对每条非约束的东西问"为什么是这样？谁规定的？如果不这样会怎样？" 大多数"必须这样"经不起追问。
3. **从地基重新推导**：只用第 1 步留下的真约束，重新推一遍这个东西"应该长什么样"。不许引用"竞品都这么做""我们一直这样"。
4. **对比现状，看差在哪**：重推的结论和现在的方案差在哪？差异处就是机会或问题所在。

**判断一条是"约束"还是"假设"**：约束 = 改了它整件事就不成立（用户一天只有 24 小时、钱要回款才是钱、人记不住超过 7 个东西）。假设 = 改了它只是"不习惯"（这个一直放侧栏、报价要先走审批、CRM 就该按客户组织）。**把假设当约束，是绝大多数平庸方案的根因。**

> 第一性原理的产物不是"颠覆一切"，而是**几条被验过的地基事实 + 一个不靠惯例支撑的结论**。

---

## 第三步：降回设计（铁律，两个动作都要做）

升上去/钻下去**只是中途**。必须回到落地，否则全是空话。

- **升维之后** → 回答：这个判断意味着页面上/方案里该出现什么、强调什么、隐藏什么、默认什么？
  - 例：页面定位从"销售看任务"升到"负责人判断这单值不值得投" → 中心就不该是聊天框，而是"证据状态 + ROI 判断 + 下一步缺口"，默认筛选改成"高风险高金额商机"。
- **第一性原理之后** → 回答：基于重推的地基结论，现状哪里要改？第一步动什么？

**一句话纪律**：高层用经营语言/地基事实定方向，底层用交互细节和具体取舍落地。只升不降，或只拆不建，都判不合格。

## 产品 UI 专用：5 层问法

讨论某个页面/组件时，按这 5 层提问（这是升维在 UI 上的具体形态）：

| 层 | 问什么 |
|---|---|
| 信息层 | 页面上到底展示哪些信息？ |
| 任务层 | 用户来这里要完成什么动作？ |
| 判断层 | 用户要基于这些信息做什么判断？ |
| 管理层 | 这个页面如何改变团队协作/资源分配？ |
| 经营层 | 这个页面如何影响收入/成本/风险/效率？ |

低级问法"左边放什么右边放什么卡片怎么排"，会让信息乱堆。先问到判断层及以上，**再**反推信息、主操作、布局、以及"不该出现的东西"。

## 输出格式

按命中的动作组织，**最后一段永远是"降回设计"**：

```
【闸门】要不要换高度：要 / 不要（一句话理由）

—— 若升维 ——
【现在在哪层】功能/场景/管理/经营/战略/时代
【5 问】① 表面做什么 ② 改变谁的决策 ③ 影响哪张账（具体）
        ④ 从 A 到 B ⑤ 反对什么旧范式
【升维结论】一两句，落到具体经营词，不用黑话

—— 若第一性原理 ——
【地基事实】拆出的几条（标注哪些是约束、哪些原以为是约束其实是假设）
【重推结论】只用真约束推出的"应该长什么样"
【和现状差在哪】

—— 永远要有 ——
【降回设计】页面上/方案里具体该出现什么、强调什么、隐藏什么、默认什么 / 第一步动什么
```

要媒体标题/定位句时，走完上面再按 `references/词表与句式.md` 第五节生成。

---

## 一句话

**不要问"这个东西怎么说得好听"，要问"它在更高层级上到底改变了什么"（升维）、"它的地基到底是什么、还成不成立"（第一性原理）——然后降回去，决定页面上出现什么。**
