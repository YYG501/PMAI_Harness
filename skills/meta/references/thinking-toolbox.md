# Thinking Toolbox（/pmai-meta）

本文件承接旧 `/pmai-meta` 的核心资产：判断标准、第一性原理、多视角压测、UI 信息 / 任务 / 判断层。它不是主流程，只能在问题会诊中被调用，服务“真问题、前提、替代方向、下一步”。

---

## 一、换高度：找更高的判断标准

换高度不是把话说得更大，而是问：这轮到底在判断什么？

| 这轮真正要判断的是 | 更高判断标准 |
|---|---|
| 企业 / 组织为什么要用、要不要投、值不值得继续做 | 经营账本：收入、成本、利润、风险、资源、时间、组织能力 |
| 个人为什么要用、用完生活哪里变好 | 人生账本：省时间、少焦虑、能坚持、值不值得花精力 |
| 工具为什么值得进工作流、长期用会不会拖累人 | 工程账本：维护成本、认知负担、出错概率、扩展代价 |
| 做不做、A 还是 B、先做哪个 | 目标账本：真正目标、代价、机会成本、可逆性 |
| 一句话 / 命名 / 定位想让人怎么理解 | 认知账本：第一眼印象、能否转述、心智坐标、行动意愿 |

用法：

1. 先说当前停在哪层：功能、场景、管理、经营、战略，或对应领域的低层表达。
2. 再问它真正改变谁的判断。
3. 最后降回页面 / 方案 / 文档：应该强调什么、隐藏什么、默认什么、让什么消失。

错法：

- 给个人使用问题硬塞“售前投入 / 资源错配”。
- 给工具维护问题硬塞“损益表 / 毛利”。
- 只说“提升认知 / 重塑流程”，没有落到具体判断。

## 二、第一性原理：拆约束和假设

当方案靠惯例、竞品类比或“我们一直这么做”支撑时使用。

四步：

1. **拆到基本事实**：哪些是真的物理、经济、人性或业务约束，哪些只是习惯。
2. **质疑每个假设**：谁规定必须这样？不这样会怎样？
3. **从约束重新推导**：只用真约束推这件事应该长什么样。
4. **对比现状**：重推结论和当前方案差在哪，差异处就是机会或问题。

判断标准：

- 约束 = 改了它整件事就不成立。
- 假设 = 改了它只是“不习惯”或“需要调整”。

产物不是“颠覆一切”，而是几条被验过的地基事实 + 一个不靠惯例支撑的结论。

## 三、多视角压测

用于已有锚点：稿子、方案、页面、规格草案、方向判断。目标是找盲区和根因，不是多 agent 投票。

默认视角：

| 视角 | 看什么 |
|---|---|
| 约束 / 真相源 | 是否违反既有决策、规格原文、业务规则 |
| 用户 / 读者 | 目标用户是否看得懂、信不信、会不会行动 |
| 业务目标 | 是否服务真正目标，是否只是功能堆叠 |
| 产品逻辑 | 用户路径、对象关系、状态变化、优先级是否成立 |
| 证据 | 结论有没有来源，哪些只是推断 |
| 表达质量 | 是否绕、空、假、大、AI 腔、口径不稳 |
| 完整性 | 关键角色、场景、异常、边界、后续项是否漏掉 |
| 可执行性 | 下一步能不能落地，是否缺输入、缺验收标准 |
| 风险 | 法务、承诺、成本、资源、误导、不可逆风险 |
| 反方 | 专门论证为什么这套东西可能不成立 |

护栏：

- 视角要互补，不要够多。
- 简单材料 2-3 个视角即可。
- 默认上限 5 个视角；超过 7 个禁止，除非 PM 明确要求且每个视角不可合并。
- runtime 没有 subagent 时，明确说“本轮按单主控多视角退化执行”，不要假装跑过独立 agent。

主控合成时必须去重、重判严重度、找冲突、找根因。PM 质疑“不合理 / 感觉不对”时，先回根因和最直接解法。

## 四、UI 信息 / 任务 / 判断层

讨论页面或组件时，先过三层：

| 层 | 问什么 |
|---|---|
| 信息层 | 页面上到底展示哪些信息？ |
| 任务层 | 用户来这里要完成什么动作？ |
| 判断层 | 用户要基于这些信息做什么判断？ |

然后按换高度结果补更高标准层：

- 经营判断：管理 / 经营影响。
- 个人使用价值：时间、焦虑、习惯、成长。
- 工具长期使用：认知负担、出错概率、维护成本。
- 取舍判断：目标、代价、可逆性。
- 表达理解：第一眼印象、能否转述、心智坐标。

低级问法是“左边放什么、右边放什么、卡片怎么排”。正确顺序是：先定这页服务谁的哪个判断，再反推信息、主动作、布局和不该出现的东西。

## 五、表达收口

当问题会诊已经得到重定位结论，再读 `词表与句式.md` 做表达校验。

表达收口只检查：

- 有没有落到对应判断标准的具体词。
- 有没有“从 A 到 B”的张力。
- 有没有说清它反对的旧范式。
- 有没有误用黑话或错域词。

最终标题、定位句、对外介绍由 `/pmai-doc-writing` 成文；本 toolbox 不直接写宣传稿。
