# /pmai-humanize · 说人话 / 打磨文字

> **它是什么**：一个文字层的纠错器。把文档里读着像机器写的、绕的、堆黑话的地方挑出来，改成简要易懂、一遍就懂的人话。
> **它不做什么**：不加新内容、不改信息结构、不改事实。**只动表达，不动信息**——一旦发现要改的其实是结构（某段该不该在、两件事该不该合），停下来交回 PM / `/pmai-design`，别在磨文时顺手改了结构。
> **金标准**：改完读起来像产品同事当面跟你讲，不像咨询报告 / 白皮书 / 营销稿。

## 治哪四样（PM 的原话）

| 病 | 长什么样 | 往哪改 |
|---|---|---|
| **啰嗦** | 长复合句、可推导的废话、堆修饰、"等 / 之类"兜底 | 拆短句、删可推导、列全 |
| **AI 味** | 满屏加粗、"不是 X 而是 Y"排比、对仗小标题、套话开场、空泛积极结尾、三连、金句、emoji | 平铺直叙、删装饰 |
| **黑话** | 工程词（鉴权 / 落库 / 颗粒度）、空词（赋能 / 抓手 / 闭环 / 拉通）、学院派凝练命名、中英混杂、代码字段路径 | 换成日常产品词 |
| **不说人话** | 抽象动词不带具体效果、主观词（清晰 / 明显）、指令视角、名词化堆叠、"本文档面向…"元描述 | 写谁做什么、什么效果 |

完整 pattern 目录（含词表分级、正反例）见 [`references/patterns.md`](./references/patterns.md)。

## 三模式

PM 发起时说哪种就走哪种；没说默认 **改写**。

- **标注（detect）**：只挑问题、不改原文。逐条引原文 + 标病种 + 给改法方向。PM 想自己改时用。
- **改写（rewrite，默认）**：挑问题 + 给整段改稿。原文 → 改稿对照，附"改了啥"。
- **就地改（edit）**：直接改文件（PM 给了文件路径、且明确"直接改"）。改完报告改动清单。

## 输入

- **对象**：PM 给的文件路径（读进来）或直接粘贴的文字。
- **语气目标**：默认「**简要易懂 / 规格平实**」。规格、PRD、说明类文档都用这个——平实就是对的，不需要温度。只有 PM 明确说"这是对外/营销稿、要有点人味"时，才放开一点（但仍不堆 AI 味）。

## 流程（多遍过，借 humanizer / avoid-ai-writing 的做法）

1. **识别**：通读，按 `references/patterns.md` 的四类逐项扫，命中处引原文标病种 + 严重度（P0/P1/P2）。
2. **改写**：逐处改。改的时候守三条判断：
   - **实用性测试**：一个短语挖空一个名词 / 形容词后意思不变，那它就是空话，删或换实词（"提升整体体验" → 具体提升了什么）。
   - **每段一事**：每段先说出它贡献的那**一件**事；说不出 = 这段在注水，砍。
   - **不改原意**：只换说法，不动事实、数字、结论、约束。拿不准是不是改了意思 → 标出来问 PM，别擅自定。
3. **二次自审**（关键，别省）：把改稿再读一遍，自问"**还有哪里像机器 / 像咨询报告？**"——尤其检查：是不是为了去 AI 味反而加了金句 / 强行口语 / 假亲切（那是另一种 AI 味）；加粗是不是还多；有没有把短句拆碎成做作的 staccato。命中再改。
4. **输出**（见下）。

> 第 3 步和第 4 步之间，有 codex 环境时可插一道「codex 冷读挑刺」（见下），用独立模型再揪一遍。没有就跳过。

## 可选：codex 冷读挑刺（独立模型二次把关）

AI 自己的二次自审（第 3 步）有个天然短板——**自己看不出自己的腔**。有 codex 环境时，再派 codex 做一道独立冷读：它没写过这稿、是另一个模型，更容易揪出残留的 AI 味和被悄悄改掉的原意。

**默认按环境决定，不强加**：先检测，没有 codex 就默认不启用、**静默跳过**（不报错、不阻断收尾）。PM 也可显式说"过一遍 codex"。

```bash
# 把原文、改稿先各自落到临时文件（$ORIG / $NEW），再检测 codex
if ! command -v codex >/dev/null 2>&1; then
  echo "ℹ️ 未检测到 codex 环境，跳过 codex 冷读（这道是可选把关，不影响收尾）"
else
  codex exec --sandbox read-only "$(cat <<PROMPT
你是一个挑剔的中文编辑，冷读下面这份"改稿"（它由"原文"打磨而来，目标是简要易懂、说人话）。
只挑问题、不要改写，逐条指出：
1. 改稿里还有哪些没改干净的 AI 味 / 黑话 / 啰嗦 / 不说人话——引出具体句子。
2. 改稿有没有改变原意、丢了原文事实点——逐点对照原文，列出丢失或走样的。
3. 有没有过度润色——造金句 / 强行口语 / 假亲切 / 把句子拆得做作（这是另一种 AI 味）。
4. 还需要改的具体位置和方向。
没问题的条目就回"这条没问题"。

【原文】
$(cat "$ORIG")

【改稿】
$(cat "$NEW")
PROMPT
)"
fi
```

**拿到 codex 的挑刺后**逐条核：

- **它对的就改**——尤其"改了原意 / 丢了事实"算 P0，必须修回。
- **它过度挑剔就挡回**——比如要求加文采 / 加金句 / 更有"感染力"，按"平实即正确"不采纳。codex 也会有自己的腔，不照单全收。
- 改完在输出末尾附一段「codex 冷读 + 怎么处理的」。

## 保嗓音红线（防过度润色 = 防反向 AI 味）

- **平实不是病**。规格 / 技术文档"平实即正确",不要为了"有人味"硬加温度、感叹、第二人称招呼。
- **不造金句、不强行口语、不假亲切**。把"重型 AI 味"改成"亲切 AI 味"是没改好。
- **不做成千篇一律的"干净"**。保留作者原有的句子节奏和用词层级，只去掉病灶，不抹平个性。
- **够了就停**。一段没病就别动它，不为改而改。

## 严重度（决定改不改、先改谁）

- **P0**（必改）：黑话 / 工程词 / 中英混杂 / 改变可读性的啰嗦 / 元描述自指——读者要二次理解或看不懂的。
- **P1**（该改）：AI 味（满屏加粗 / 否定排比 / 套话开场结尾 / 三连 / 金句）、抽象动词无效果、主观词。
- **P2**（顺手）：轻度冗余、句子节奏、可并可拆的小处。
- **全文重写信号**：当一段里 P0/P1 命中 5 处以上 + 句子 / 段落长度高度均匀（典型机器节奏），别逐句补，整段重写更快。

## 输出格式

**标注模式**：

```
## 挑出的问题（共 N 处）
1. [P0·黑话] 原文："……" → 改法：……
2. [P1·AI味·满屏加粗] 原文："……" → 改法：……
```

**改写模式**：

```
## 问题清单（引原文 + 病种）
- …

## 改稿
（整段 / 整篇改写后的文字）

## 改了啥（一句话级摘要）
- …

## 二次自审
（"还有哪里像机器" 这一遍又抓到并改掉的）
```

**就地改模式**：直接改文件，末尾给「改动清单 + 二次自审」两段。

## 和 prd-writing 的关系

- prd-writing 写完 spec / PRD 后**打磨文字的收口步**（S5 / P3.x）可直接调本 skill 当统一引擎：`/pmai-humanize <文档路径>`，按"简要易懂 / 规格平实"语气跑改写。
- 本 skill 也能脱离 prd-writing，对任意 markdown 文档单独跑（会议纪要、对外说明、readme 都行）。
- pattern 目录与 prd-writing 的禁用清单 / 风格卡同源：`references/patterns.md` 引用 `skills/prd-writing/references/writing-rules.md`（8 类禁用 + 简要易懂语体）和 `skills/_shared/pm-view/writing-rules.md`（§3.12 工程黑话词典）为权威，不另立矛盾的一套。
