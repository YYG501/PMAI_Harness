# 说人话 pattern 目录（中文）

> 本目录是 `/pmai-humanize` 的扫描清单，按 PM 关心的四类病组织：啰嗦 / AI 味 / 黑话 / 不说人话。
> 中文 pattern 为主，并入了社区英文 skill（blader/humanizer、conorbronsdon/avoid-ai-writing）里**中文也通用**的几条。
> 权威同源：禁用清单 + 简要易懂语体以 `skills/spec-writing/references/writing-rules.md` 为准；工程黑话词典以 `skills/_shared/pm-view/writing-rules.md` §3.12 为准。本目录不另立矛盾规则，只做面向"任意文档打磨文字"的汇总。

---

## 一、啰嗦（删字、拆句、列全）

| pattern | ❌ | ✅ |
|---|---|---|
| 长复合句 | 一句话里塞步骤 + 过滤规则 + 字段细节 | 流程概述一句（先 X → 再 Y → 然后 Z），细节另起分条 |
| 可推导的废话 | "候选范围 = 用户所属部门 ∩ 该产品挂载的池" | "该用户所属部门下、该产品的所有池"（自然展开的结果不必再解释） |
| 堆修饰 | "非常重要的、关键性的、核心的一步" | 删掉叠加形容词，留一个或不留 |
| 兜底词 | "编辑 / 删除等操作"、"PPT 之类的材料" | 列全："编辑、删除两个操作"；"PPT、话术、对齐清单" |
| 重复展开 | 同一规则在三处各展开一遍 | 主写一处，其余引用名称 |
| 冗长错误文案 | 一整段解释为什么不能点 | "无下载权限，请联系管理员" |

判据：**实用性测试**——一个短语挖空一个名词 / 形容词后意思不变，它就是空话，删或换实词。

## 二、AI 味（平铺直叙、删装饰）

| pattern | ❌ | ✅ |
|---|---|---|
| 满屏加粗 | 几乎每隔一句一处 `**…**` | 一段最多一两处，只加真关键词 |
| 绕弯 / 否定排比 | "这不是简单的 X，而是 Y"、"不止是 A，更是 B"——先否定一遍再翻转，本质是兜圈子 | 只留翻转后那一半，整句删掉否定前半："X 是 Y" |
| 对仗小标题 | "主动产出，待办露头"、"一键直达，体验闭环" | 用名词化标准标题："待办生成"、"快捷入口" |
| 套话开场 | "在本文中，我们将探讨…"、"随着……的发展" | 删，直接进正题 |
| 空泛积极结尾 | "总之，这将极大提升用户体验，带来无限可能" | 删，或换成一句可验证的具体结论 |
| 三连（rule of three） | 凡事都凑三项排比"高效、智能、便捷" | 该几项就几项，别凑数 |
| 金句 / 强行punchline | "数据不会说谎。"独立成段制造戏剧感 | 删，正常陈述 |
| emoji / 装饰符 | 标题带 ✨🚀、正文 → ✘ ✅ ⚠️ | 去掉（功能性勾叉除外） |
| 弯引号 / 方角引号 | "…"、「…」 | 统一半角 `"…"`；按钮 `[…]` |
| 破折号堆砌 | 用 —— 串起一长串补充 | 拆成短句或用逗号 |

判据：**二次自审**——去 AI 味时别走反面（加金句 / 强行口语 / 假亲切 / 把句子拆成做作的短促节奏，都是另一种 AI 味）。

> **视频 / 口播 / 传播文案另加一条硬约束：直给、简短精炼。**
> AI 最爱"绕"——靠"不是 X，而是 Y""不止 A，更是 B"这类先否定再翻转的句式撑场面。写文档里只算 AI 味，放进视频脚本里就是硬伤：观众没耐心听你兜半句再翻回来。改法是只说结论那一半（"X 是 Y"），把否定的前半句**整句删掉**，不做转折、不做铺垫、不堆排比。一句话能讲完的不拆成三句。

## 三、黑话（换成日常产品词）

**工程词**（任何面向产品 / 业务的文档都不出）：

| ❌ | ✅ |
|---|---|
| 鉴权 | 权限判断 |
| 落库 / 持久化 | 存下来 |
| 颗粒度 | 粗细 / 细到什么程度 |
| 链路 | 流程 / 一条线 |
| 派生 / 漂移 | 算出来的 / 跟原来对不上了 |
| 悬挂引用 | 引用了一个已经不存在的东西 |
| 句柄 / 钩子 / reducer | 用产品语言描述它干什么 |
| 字段名 / 路径 / 代码常量 | 用产品功能名指代 |

**空词 / 互联网黑话**（说了等于没说，删或换实指）：

赋能 / 抓手 / 闭环 / 拉通 / 打通 / 对齐 / 收口 / 沉淀 / 心智 / 卡位 / 组合拳 / 强抓手 / 全链路 / 端到端 / 顶层设计 / 生态位 —— 一律换成它**具体指的那件事**，换不出来就是没想清，删。

**学院派凝练命名**（4-6 字抽象短语，要查内容才懂）：

| ❌ | ✅ |
|---|---|
| 显式归因 | 每一笔都关联一张凭证 |
| 多维度对称 | 各维度按相同结构分账 |
| 状态联动 | 凭证失效时额度池一并失效 |
| 凭证执行分离 | 凭证管理只看凭证，执行另算 |

**中英混杂**：review→核对 / CRUD→列全创建编辑删除 / scope→范围 / prompt→提示词 / SaaS / POC / business case → 给中文产品词。

## 四、不说人话（写谁做什么、什么效果）

| pattern | ❌ | ✅ |
|---|---|---|
| 抽象动词不带效果 | "保存后立即更新定义" | "保存后，所有用到它的地方立刻按新规则生效" |
| 主观词 | "清晰区分默认角色"、"明显标识" | "默认角色那行带'默认'标识" |
| 指令视角 | "想清空请走取消分配" | "清空额度池通过'取消分配'操作" |
| 名词化堆叠 | "实现订单状态的自动化流转管理" | "订单状态自动往下走" |
| 没主语 | "需要进行确认" | "由架构师确认" |
| 元描述 / 自指 | "本文档面向研发评审"、"为了让 PM 讲清楚…" | 删，文档不描述自己 |
| 视觉细节越界 | "红色 destructive 按钮、#CB2634" | "删除按钮"（颜色样式归设计稿，文档不写） |

判据：**每段点出它贡献的那一件事**；点不出 = 在注水。

## 词表分级（扫描效率，借 avoid-ai-writing 的分级）

- **必换（出现就改）**：赋能 / 抓手 / 闭环 / 拉通 / 鉴权 / 落库 / 颗粒度 / 链路 / delve 类英文词 / 满屏加粗 / "不是X而是Y" / emoji。
- **密集才 flag（一段里 ≥2 个才算病）**：沉淀 / 对齐 / 承接 / 派生 / 覆盖 / 优化 / 提升 —— 单个出现可能是正常用词，扎堆才是 AI 味。
- **高密度才 flag**：重要 / 关键 / 核心 / 有效 / 显著 —— 通篇高频出现才提。
