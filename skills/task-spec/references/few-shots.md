## 🎯 关键产品决策 示例

```markdown
## 🎯 关键产品决策

| # | 决策项 | 当前选择 | 备选方案 |
|---|---|---|---|
| 1 | 角色管理的「默认角色」与「scope」的关系如何表达 | 角色定义不携带 scope；分配时由 `code === "TENANT_ADMIN"` 硬编码锁定全租户，其他角色自由 | 在角色定义中加 `scopeConstraint` 字段（增加模型复杂度，租户管理员仍需特例）|
| 2 | 角色定义权（创建 / 编辑 / 删除 / 启用停用）默认授予对象 | 仅租户管理员；部门管理员要做角色管理需被显式授予对应权限点 | 默认两类管理员都可（导致部门管理员越权风险，"自提权防护"逻辑变复杂）|
| 3 | 角色详情页结构 | 顶部扁平区 + 2 Tab（权限配置 / 授权对象）| 3 Tab（基本信息 / 权限配置 / 授权对象，原方案；信息槽位重复）|

> 决策的共同理由：V4.1 的核心是"角色定义只回答能做什么、scope 只在分配时谈"。决策 1 / 2 都源自这一根命题；决策 3 是基于"信息不重复"原则在 PM 实测后的简化。
```

**写作要点**：
- "决策项"列必须明确**在哪个页面 / 哪个区域，对什么对象，做什么决策**——不能只写"如何处理 X"
- "当前选择"用业务语言完整描述；不写实现细节
- "备选方案"至少 1 个，注明取舍
- "共同理由"集中放表格下方一段；不在每行的"备选方案"里重复
- 纯执行型 task（无 PM 决策点）：删表，写一行 `本 task 无关键产品决策（执行 solution.md §X.Y 已确定方案）`

```
**关键交互说明**：
- 「受限视图提示」仅在当前登录用户为部门管理员时出现；若被显式授予了"角色创建/编辑"权限点则不展示。
- 「+ 创建自定义角色」按钮仅租户管理员（或被授予"角色创建"权限点的用户）可见，部门管理员看不到。
- 操作列：默认角色只展示"查看"；自定义角色展示"查看 / 编辑 / ⋯（启用停用 / 删除）"，按当前用户的权限点动态隐藏。
- 列表行的描述列采用省略 + max-width，长描述不挤占右侧字段（具体视觉规范见 `docs/DESIGN.md` §列表页列宽约束）。
```

**写作要点（§3.10 五类反例对照）**：

| 反例类别 | 错误写法（骨架内不要出现） | 正确做法 |
|---|---|---|
| 默认值标注 | `席位：1（独占，固定）` | `席位：1`（屏幕字）；"独占"语义下沉到 §交互说明 |
| 文档元注释 | `─（新增·简化版）─` / `（仅租户管理员可见）` | 整段删除；变更范围 / 角色限制说明在 §📋 功能清单 已有 |
| 设计意图 | `┝ 旧版授权（已吊销，弱化）─┥` | 屏幕字保留状态名「已吊销」；视觉弱化进 §交互说明，引 `docs/DESIGN.md` |
| 字段口径解释 | `配额（按产品维度集动态显示）` | 屏幕字保留入口名「配额」；动态显示规则进 §交互说明 |
| 折叠藏默认值 | `[▸ 高级配置]   ← 默认值藏在这里` | 默认值直接渲染；override 走单独按钮 |

启发式 lint `check-doc-pm-view.py` 会对骨架代码块内出现的 `（...）` 报 warning，由 PM/AI 自判合法标识型（CSV / 1080p）vs 非法释义型（基于 X / 多 Y 场景）。

## 📋 功能清单 示例（4 列表格 + 续行 rowspan + 需求描述列内联编号）

```markdown
## 📋 功能清单

### 1 · 「角色管理 - 角色列表页」

> **使用角色**：租户管理员；部门管理员（仅在其管辖范围内的可见性）

|---------|---------|---------|---------|
| 角色列表 | 列表展示 | 租户管理员；部门管理员 | 1. 展示当前租户角色列表，全租户可见。 |
| | | | 2. 默认展示字段：角色名称、角色类型、描述、权限数、授权用户数、状态、创建时间（可排序）、创建人、更新时间（可排序）。操作列：查看详情、编辑、更多（启用停用 / 删除）。 |

| | | | 4. 默认角色需在列表中清晰标识（如"默认"标签）。 |

| | | | 3. 支持按角色类型筛选（默认角色 / 自定义角色）。 |
| | | | 4. 支持"重置"按钮，一键清空所有筛选条件。 |
| 角色列表 | 排序与分页 | 租户管理员；部门管理员 | 1. 默认按创建时间倒序。 |
| | | | 2. 支持按更新时间排序。 |
| | | | 3. 支持分页浏览，翻页后保留当前筛选与排序。 |
| 角色列表 | 快捷操作 - 编辑 / 启用停用 / 删除 | 租户管理员 | 1. 这些操作仅对租户管理员展示（部门管理员默认不含对应权限点，按钮直接隐藏）。 |

```

**写作要点**：
- **续行 rowspan 模式**：同一三级功能的多条需求 → 第 2 条起的前 3 列**留空**；视觉等同 rowspan，纯 markdown 也能渲染
- **二级功能跨多个三级功能**：同一二级功能字符串可在多行重复出现（不强制收敛 rowspan 在二级功能列）
- **字段定义、计算口径、边界规则**：直接写进需求描述列的某条编号项；**不另起字段口径独立表**
- **需求描述列编号项**：每条 1. / 2. / 3. ...，过 §5.2「换 UI 还成立」判别简则
- **section 级 `> **使用角色**：` blockquote**：本节整体角色统一时写在表前；逐行不同则只填表内列
- **表后 `> **注**：` blockquote**：可选，写本节额外约束 / 边界

## 🚦 跨功能产品规则 示例

```markdown
## 🚦 跨功能产品规则

1. 角色定义不携带 scope 约束字段；scope 仅在分配时由 `ScopeField` 控件指定。
2. UI 标签统一为「权限范围」（不用「适用范围」）；radio 文案统一为「全租户 / 指定部门」。
3. 详情页字段不重复：状态、权限点数、授权用户数、创建人、创建时间、更新时间、描述在顶部摘要卡展示后，Tab 内容里不再重复。
4. 已停用角色不能被新分配（历史授权关系保留、不参与实时鉴权）。
5. 自提权防护在原型阶段只做前端提示与禁用，不做真实后端拦截；落地时机由后续 task 决定。
```

**写作要点**：
- 来自同模块已完成 task 的 PM 反馈中"正向规则"类条目（PM-VIEW-RULES §9.4 三类分流的第一类）
- 跨多个功能的共同业务规则（统一文案 / 统一行为 / 数据闭环关系）
- 每条 1-2 句完整描述，不缩略；正向句式
- 本 task 无跨功能规则 → 删掉本 section
