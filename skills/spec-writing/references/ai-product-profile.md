# AI 产品 Profile

> 本 Profile 适用于 Agent、生成式模型、智能判断、内容生成、自动分析或 AI 评测参与产品主流程的功能。它叠加在 `content-modules.md` 之上，不定义另一套 PRD 目录。

## 触发判断

出现以下任一情况时启用：

- AI 输出直接影响用户判断、任务或业务动作；
- Agent 会主动触发、生成建议、修改候选内容或调用工具；
- 产品需要人工确认标准答案、关键事实或高影响动作；
- 需要评测集、Evaluator、模型/方案版本、红线或回归评测；
- AI 失败、不确定或依据不足时需要明确降级。

只有普通搜索、固定规则推荐或不影响产品行为的文案生成时，不必完整启用；按实际风险选取相关检查项。

## 叠加规则

### 角色与责任补充

每个 AI 场景先写清：

| 内容 | 要回答的问题 |
| --- | --- |
| 场景目标 | AI 帮用户完成哪个业务结果？ |
| 触发 | 用户、事件、状态还是定时任务触发？ |
| 输入与依据 | AI 可以读取什么，来源和适用时间是什么？ |
| AI 输出 | 生成事实、推断、建议、草稿还是动作候选？ |
| 人工责任 | 谁确认业务真相、标准答案和高影响动作？ |
| 确定性系统责任 | 谁执行权限、状态、门禁、版本、审计和不可逆操作？ |
| 完成条件 | 什么结果才算本次协作完成？ |

不得让 AI 输出自动成为已确认事实、正式标准或线上变更。

### 信息模型补充

按需区分：

- 原始输入与可追溯依据；
- AI 推断、候选内容和置信/不确定性；
- 人工确认结论；
- 正式生效对象与历史版本；
- 评测样本、预期结果、Evaluator 和运行结果。

这些对象不能用一个“状态”混在一起。建议处理结果、人工决策、发布结果和运行结果分别记录。

### 核心动作补充

每个 Agent 或 AI 动作补充：

- 触发原因和使用的版本；
- 输入来源、数据时间和权限边界；
- 输出格式、依据、不确定性与缺口；
- 用户可执行的接受、修改、拒绝、重试、暂缓或撤销动作；
- 哪些内容变化会使旧输出过期或触发重算；
- 失败、超时、部分结果和工具调用失败时的降级；
- AI 输出如何进入正式对象，谁负责确认；
- 高影响动作的确定性门禁与审计。

Agent 可以主动分析和提案，但不能静默改写已确认内容，不能自行扩大权限，也不能绕过发布或审批。

### 事实、推断与建议

文档必须定义产品如何区分：

1. 已确认事实；
2. 外部来源但尚未确认的信息；
3. AI 推断；
4. AI 建议或草稿；
5. 人工确认结论；
6. 已执行的业务结果。

展示样式属于设计资产；PRD 只定义这些信息在产品中的可辨识性、可追溯性和可操作行为。

### 评估与评测补充

评估一个完整用户 Case，不只评估单次模型调用。根据业务目标选择维度，例如：

- 结论或产物正确性；
- 依据充分性与可追溯性；
- 缺失、冲突和不确定性处理；
- 例外与边界处理；
- 建议动作是否有效且不越权；
- 用户能否理解并完成下一步。

关键红线不能被平均分抵消，例如编造事实、重要漏判、越权动作、泄露敏感信息或未经确认直接生效。

评测集要求按需写清：

- 样本来源和覆盖分类；
- 输入、预期结果和不可接受结果；
- 谁确认业务标准和数据条件；
- 适用的产品/方案版本与 Evaluator 版本；
- 每类证据能证明什么、不能证明什么；
- 变化后的回归和版本管理。

没有历史数据、基线或可靠阈值时，写验证计划，不虚构样本和数字。

### 异常与空状态补充

除通用异常外，检查：

- 输入不足或相互冲突，AI 无法可靠判断；
- AI 输出低置信、违反格式或命中安全红线；
- Agent、模型、工具、检索或外部服务失败；
- 输出生成中、等待人工确认、失败和完成的状态；
- 上游事实变化后旧建议失效；
- 人工修改与 Agent 新结果发生冲突；
- 重试是否复用输入、是否产生新版本、是否覆盖旧结果。

失败不得改变已确认事实、正式评测标准或当前生效版本。

### 验收补充：Case Rundown

高风险或闭环型 AI 产品使用 Case Rundown 验收。主 Case 从业务目标开始，至少覆盖：

1. 输入或场景触发；
2. AI 分析/生成与依据展示；
3. 人工确认或校准；
4. 确定性门禁与正式生效；
5. 真实使用结果或反馈回流；
6. 问题分析、修改和回归验证。

支持 Case 覆盖依据缺失、冲突、AI 失败、错误建议、权限不足、并发修改、发布失败和回滚。产品功能验收与经营价值验证分开：闭环可运行不等于价值假设已经成立。

## 与企业平台 Profile 的组合

产品同时具备企业平台治理和 AI 主流程时，同时加载 `enterprise-platform-profile.md`。确定性权限、状态、版本、发布、回滚和审计仍由平台系统负责；AI Profile 只补充智能行为、人机责任和评测合同。

## 交付检查

- 每个 AI 场景是否有触发、输入、输出、人工确认和完成条件？
- 事实、推断、建议、人工决定和执行结果是否分开？
- AI 失败或不确定时是否有明确降级？
- 高影响动作是否由确定性门禁和人负责？
- 评估是否覆盖完整业务 Case，红线是否独立？
- 是否避免虚构数据、阈值、模型能力和自动学习闭环？
