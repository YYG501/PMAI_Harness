# 完整 PRD Preset

> 本文件只定义完整 PRD 的章节编排。章节内容来自 `content-modules.md` 和适用 Profile；Preset 不引入新的产品规则。`templates/prd.md.tmpl` 是唯一完整 PRD 模板。

## 何时使用

PM 明确要求 PRD、完整研发评审稿或跨角色交付合同时使用。模块 `spec.md`、规则收口、状态说明、字段口径和轻量功能规格不套本 Preset。

完整 PRD 必须先通过产品方向 gate：读取当前 Product Proposal，或读取 PM 已确认仍有效的完整等价产品基线。两者不是可任选的参考材料，而是本次成文的上游依据；新项目或产品级判断不完整、漂移时，必须先返回 `/pmai-proposal` 完成判断，不能为了成文跳过该 gate。

## 唯一章节编排

| 顺序 | 章节 | 主要内容模块 |
| --- | --- | --- |
| 摘要 | 范围与结果概述 | M1 |
| 一 | 文档信息 | 版本、状态、负责人、上游依据 |
| 二 | 变更日志 | 当前文档变化，不写讨论过程 |
| 三 | 背景、目标与范围 | M1 |
| 四 | 用户、角色与场景 | M2 |
| 五 | 信息模型 | M3 + Profile 补充 |
| 六 | 核心动作 | M4 + M5 + Profile 补充 |
| 七 | 异常与空状态 | M6 + Profile 补充 |
| 八 | 验收标准 | M7 + Profile 补充 |
| 九 | 非功能要求 | M8 |
| 十 | 附件与参考材料（可选） | M9 |

章节可以省略没有实际内容的附件，但不能省略信息模型、核心动作、异常与空状态、验收标准四个主干章节。简单对象可在信息模型中用短定义，不强制大表。

## Profile 如何进入 Preset

Profile 不增加第二套目录，直接补进对应章节：

- 企业平台 Profile：补充租户/组织边界、对象关系、权限、生命周期、外部接入、迁移、审计和治理验收；
- AI Profile：补充人机责任、AI 对象、触发反馈、事实与建议边界、失败降级、端到端评测和 Case Rundown；
- 企业 AI 平台：同时应用两份 Profile，不使用第三个组合 Profile。

确有大量权限数据、字段字典或评测样本时放附件；核心行为仍在正文。

## 核心动作章节写法

每个 `6.x` 对应一个稳定业务动作组，每个 `6.x.y` 对应一个核心动作。动作详情按需要使用以下小节，不为凑格式强制全部出现：

```markdown
### 6.x <动作组>

#### 6.x.1 <核心动作>

- 目标与角色：
- 触发与前置条件：
- 输入与校验：
- 处理规则：
- 结果与状态变化：
- 权限与数据范围：
- 失败与恢复：
```

字段很多时在动作下加字段表；角色差异多时加权限矩阵；多步流程用顺序叙述。不要把全部内容压进一张表。

## 4 列动作索引（可选）

只有复杂管理后台包含大量创建、查看、编辑、启停、移出、删除等动作时，才可在第六章开头增加索引：

| 动作组 | 核心动作 | 使用角色 | 详情位置或一句摘要 |
| --- | --- | --- | --- |

索引只帮助扫描，不承担完整需求。规则：

- 动作组和核心动作按业务动作命名，不用页面、Tab、弹窗或 Drawer 命名；
- 每个索引项必须有后续动作详情，不能只留表格；
- 字段、前置条件、状态联动、异常和验收不得塞进索引单元格；
- 简单 PRD 不生成索引；
- 选择索引时保留 P2.5 拆分确认和 `check-prd-hierarchy.py` lint。

## AI 产品的验收扩展

启用 AI Profile 时，第八章在常规验收之后按需增加：

- 端到端评估维度与红线；
- 评测集要求和版本关系；
- 主 Case Rundown；
- 高风险支持 Case。

这些内容仍属于验收，不另造一个“AI PRD Preset”。

## 交付检查

1. 章节内容是否都能追到已确认决定？
2. 信息模型是否先于动作，动作是否覆盖状态、权限和结果？
3. 异常与验收是否覆盖正常路径之外的行为？
4. Profile 是否只追加领域检查，没有复制通用章节？
5. 4 列表是否只是可选动作索引？
6. 产品级前提缺口是否返回 Proposal，模块决定缺口是否返回 design？
