# §八 自检清单（生成 / 修改 PM 视图后）

> 本文件是 [`PM-VIEW-RULES.md`](../PM-VIEW-RULES.md) §八 的物理拆分。配套阅读：[`writing-rules.md`](./writing-rules.md)（§三）/ [`section-order.md`](./section-order.md)（§七）。条目里的 §3.X / §5.X 引用指向 `writing-rules.md`；§七 引用指向 `section-order.md`。

每次写完 PM 视图，AI 自检以下 12 项：

- [ ] 文档章节顺序符合 §七 约束（见 `section-order.md`）
- [ ] 所有名词带完整指代前缀（§3.1）
- [ ] 无像素值 / 颜色码 / Emoji 视觉（§3.2）
- [ ] 无反向约束（**显式** "禁止 / 不允许 / 禁用"+**隐式** "无 X / 没有 X / 不出现 X / 不通过 X"，§3.4）；§📦 范围 / §✅ 验收清单 / §📋 编号项陈述事实 已在 lint section 豁免，其余场景一律改正向
- [ ] 无组件实现名（reducer / props / hook 等，§3.2）
- [ ] 无设计意图解释（"避免 X" / "防止 Y" / "为了 Z" / "确保 X"，§3.2 — lint 抓括号内开头的"避免 / 防止 / 确保 / 为了 / 以防"）
- [ ] 抽象动词都搭配具体效果（§3.5）
- [ ] 功能需求写法匹配内容形态（规则 / 状态 / 流程 / 字段 / 权限 / 动作清单）。只有选择 4 列功能表 preset 时，才检查 4 列表格 + 续行 rowspan + 需求描述列内联编号（见主文件 §五）
- [ ] **无反引号代码引用 / 中英混杂业务词（admin / scope / active / pending / null / breakdown / mock / self-contained 等）/ 数学符号（∩ ⊊ ⊆ 等）/ URL 参数字面量（tab=pools&view=dept 等）**（§3.8）
- [ ] **UI 骨架代码块内只有屏幕字**——无设计意图标注、字段口径解释、文档元注释、默认值标注、折叠藏默认值（§3.10 五类反例）
- [ ] **UI 骨架宽度 ≤ 80 字符**（§3.10.1 硬约束；超出说明紧凑行用了完整业务名而场景不合适，改用维度简称与"产品详情页 Tab 1 池行" convention 对齐）
- [ ] 业务规则过「换 UI 还成立」简则；若当前不是 4 列功能表，不要为满足表格检查把规则收口、状态分类、流程叙述强拆成二级 / 三级功能（见主文件 §5.1-§5.4）

当前没有 task 文档 lint 兜底；语义判断（指代是否完整、抽象动词是否搭配具体效果、§5.3「换 UI 还成立」判别）必须靠本节自检 + reviewer。若后续补机器检查，只能针对当前模块三件套 / PRD 结构，不能复活旧 task-plan 检查器。
