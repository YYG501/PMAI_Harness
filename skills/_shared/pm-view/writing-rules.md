# §三 PM 视图写作规则（硬约束）

> 本文件是 [`PM-VIEW-RULES.md`](../PM-VIEW-RULES.md) §三 的物理拆分。配套阅读：[`doc-strictness.md`](./doc-strictness.md)（§四 文档级严格度对照表）。

适用：所有 PM 视图层文档 — `brief.md` / `analysis.md` / `solution.md` / `task-plan.md` / `tasks/task-NNN-*.md` / `prd.md`。

---

## 如何补新规则（反馈循环 SOP）

当 PM 复审 PRD / task spec 等产物发现新违规词时，按以下 5 步补：

1. **加规则**：到本文件对应子段（§3.1-§3.12）的 ❌/✅ 对照表，加一行违规词 + 正确写法。
2. **加 lint pattern**：到 `scripts/check-prd-hierarchy.py` 对应 PATTERN 列表（VISUAL/URL/PUNCT/NEG/JARGON_PATTERNS）。pattern 用 `(regex, reason_with_hint)` tuple，让 lint 输出能给具体改写建议。
3. **（可选）加 few-shots 反例对照**：到 `skills/prd-writing/references/few-shots.md` §描述风格修订对照 对应子段，加反例 → 正例 pair（LLM 风格学习用，不机械抓）。
4. **跑回归测试**：`scripts/tests/run-tests.sh` 确保旧规则不破坏。
5. **跑回测**：用本次发现违规的真实 PRD 跑新 lint，验证抓得到；抓到的处数写到 commit message。

跨 skill 复用：本文件改动自动覆盖所有 PM 视图 skill（prd-writing / task-spec / publish-to-lark 等），无需逐个改。

---

## 3.1 每个名词必须明确指代

PM 视图里出现的每个名词，必须能让读者一眼知道**指代哪个对象 / 哪个页面 / 哪个区域 / 谁的属性**，不允许模糊指代。

| 模糊（❌）| 明确（✅）|
|---|---|
| 树最上面那一层 | 「产品详情页 - Tab 1 额度分配视图」的树形列表，最顶层节点 |
| 状态 Badge | 许可证状态 Badge |
| 状态列 | 许可证状态列 |
| 弹窗 | 「分配额度弹窗」 |
| 列表 | 「产品访问管理 - 产品列表页」的产品列表 |
| 失效证 | 状态为已失效（含已过期 / 已停用 / 已吊销 / 未生效）的许可证 |
| admin | 租户管理员 / 部门管理员（仅在其权限范围内的部门）|
| Tab 2 不动 | 「产品详情页 - Tab 2 用户开通（task-004 实现）」保持现状不动 |

**自检**：单字"状态"、"列表"、"树"、"弹窗"、"操作"、"按钮"、"用户"出现时，前面必须有完整指代前缀。

## 3.2 只描述功能行为

PM 视图回答：
- 系统应该提供什么
- 用户能做什么
- 业务规则是什么
- 数据字段之间的关系是什么
- 角色权限是什么
- 异常路径如何呈现

PM 视图**不**回答：

| 类别 | 不出现 | 替换为 |
|---|---|---|
| 像素值 | 24px / 420px / w-14 / py-5 | 移到工程合同 |
| 颜色码 | #C9CDD4 / #FFA39E | 移到工程合同 |
| 文字色名 | "红色文字" / "黄色警告" | "视觉高亮" / "视觉弱化" / "警告信息"（语义保留）|
| Emoji 视觉 | 🟡🔴⚫ | 移到工程合同；状态文案保留（未生效 / 已过期）|
| 反向约束 | "禁止 X" / "不允许 Y" | 移到工程合同；正向改写"系统不保留 Y"|
| 设计意图解释 | "（避免双重计数）" / "（防止角色爆炸）" | 移到「关键产品决策」的"共同理由"行 |
| 组件实现名 | reducer / dispatch / props / hook / useReducer / useState | 移到工程合同 |

## 3.3 保留产品视角行业词（含指代前缀）

所有 PM 视图文档都可以使用产品视角的 UI 行业词，但**必须**加完整指代前缀，让读者一眼知道指代哪个对象：

| 行业词（保留） | 必须加的指代前缀（举例）|
|---|---|
| Badge | 许可证状态 Badge / 部门额度状态 Badge |
| Drawer | 「额度明细 Drawer」 / 「用户详情 Drawer」 |
| Tab | 「产品详情页 - Tab 1 额度分配视图」 |
| Tooltip | 鼠标悬停时给出的说明性提示 |
| Toast | 系统给出成功反馈（Toast 形式）|
| Dialog / 弹窗 | 「分配额度弹窗」 / 「调整额度弹窗」 |
| 折叠区 | 「已失效」折叠区 |

## 3.4 正向描述系统行为

PM 视图用正向句式。**隐式反向（"无 X / 没有 X / 不出现 X / 不通过 Y"）等同于显式反向（"禁止 / 不允许"）**——同样要改写正向。

| 反向（❌）| 正向（✅）|
|---|---|
| 系统不允许保留中间态 | 系统将所有改动整体回滚到操作前的状态 |
| 禁止在该行额外添加文字标签 | 该行以视觉高亮方式区分 |
| 禁用「含子」概念 | UI 文案统一使用"勾选部门"的实操描述 |
| 行末**没有**跳转或操作入口 | 失效证仅供查看，管理员通过「租户配置 - 许可证管理」主入口处理 |
| **不出现**任何跳转入口 | 同上——描述系统提供什么 / 通过哪个入口处理 |
| **不通过**抽共享组件保证 | 由 PM 走查对照保证 |
| **不展示**「已用 / 剩余」两列 | 每维度展示总额单值 |

反向约束（"禁止 / 不允许 / 不准 / 禁用 / 不得 / 不出现 / 不展示 / 不通过 / 没有...入口"）一律移到工程合同。

**例外（lint 自动豁免）**：
- §📦 范围 描述本 task 移除/不再保留 X：天然反向，是 scope-change 描述（如"行展开内子行不再保留 [查看 ↗] 入口"）
- §✅ 验收清单 列出 PM 走查项时用"verify X 不出现"句式：天然反向，验证视角友好（如"不出现英文字段名"）
- §📋 编号项陈述当前数据未触发某规则的事实（如"当前数据下不出现「+N 个其他维度」提示"）：事实陈述而非反向约束

## 3.5 抽象动词必须搭配具体效果

以下动词出现时必须紧跟具体效果或对象：

| 动词 | 必须补全 |
|---|---|
| "更新 X 定义" | 更新后，对持有 X 的对象立即按新规则生效 |
| "保存后生效" | 生效后什么变化、对谁生效 |
| "立即更新" | 更新的具体内容 |
| "执行 X 操作" | 操作的具体步骤或结果 |

| 模糊（❌）| 完整（✅）|
|---|---|
| 保存后立即更新角色定义 | 权限点保存后，所有持有该角色的启用用户立即按新权限点鉴权 |

## 3.6 文档自包含

- 关键规则的简要说明应直接写在当前位置；同一规则在多处出现，每处都简要描述（约 1-2 句）。
- 禁止用「详见 §6.X」让读者跳转。
- "详见 §X" 仅用于引用本文件之外的文档（如 `docs/DESIGN.md`）。

## 3.7 禁用兜底词 / 主观词

| ❌ 错误 | ✅ 正确 |
|---|---|
| "编辑 / 启用停用 / 删除"等操作 | "编辑"、"启用 / 停用"、"删除"三个操作 |
| 默认角色清晰区分 | 默认角色行带"默认"标识 |

兜底词（"等"、"之类的"、"相关的"）必须列全所有项。

## 3.8 禁用书面冷僻词 / 中英混杂 / 技术 jargon / 数学化表达

| 类别 | ❌ 错误 | ✅ 正确 |
|---|---|---|
| 冷僻词 | 明示 / 暗中 / 链路 / 范畴 / 颗粒度 | 替换为日常中文（提示 / 隐含 / 流程 / 范围 / 粒度）|
| 中英混杂（业务词）| review / CRUD / scope / admin / breakdown / mock / self-contained / workflow / pipeline | 评审 / 创建-编辑-删除-启用停用 / 管辖范围 / 管理员（角色名首次出现可用"租户管理员 / 部门管理员"）/ 明细 / 模拟 / 各自独立 / 流程 / 流水线 |
| 中英混杂（状态字面量）| active / pending / null / undefined | 已激活 / 待生效 / 无值 / 未设置 |
| 中英混杂（数学/集合/函数）| sum / count / map / filter / reduce | 累加 / 统计 / 按 X 归并 / 按 X 筛选 / 合并 |
| 中英混杂（数据结构 / 实现词）| schema / record / props / hook / reducer / dispatch / topContent / kebab / segmented control | 这些是工程词，全部驱逐到 `*.engineering.md`（见 §3.2）|
| 反引号代码引用 | `\`quotaPoolId=null\`` / `\`useState\`` | 反引号包裹的代码 / 字段 / API 名 一律不出现在 PM 视图 |
| URL 参数字面量 | "URL 带 tab=pools&view=dept 查询参数" | "详情页直接定位到 Tab 1 额度分配视图、部门视角"——描述跳转结果而不是 query string |
| 技术 jargon | 悬挂引用 / 互锁陷入死锁 / 不参与鉴权 | 仍引用了不存在的对象 / 双方互相阻止对方操作 / 不参与权限判断 |
| 数学化表达 | 严格小于 / ⊊ / ⊆ | 完全包含在 X 之内（且至少少一个）|

**例外**：UI 行业词（Badge / Drawer / Tab / Tooltip / Toast / Dialog 等）允许保留，参见 §3.3。

## 3.9 禁用元描述 / 自指

文档内不出现对自身的描述：
- "本文档是产品规格交付层"
- "本文档面向研发评审"
- "如何使用本文档"
- "为了让 PM 讲清楚……"

## 3.10 UI 骨架代码块内只写"屏幕上的字"

`§🖼 页面 UI 骨架` 章节里的 ASCII 框图代码块（` ``` ` 围起来的那段），**只允许出现 admin / 用户在屏幕上实际能看见的文案**。任何对字段、区块、状态的解释、注释、设计意图、口径说明 → 全部剥离到骨架代码块**下方**的「关键交互说明」段。

**反例对比**（一个浓缩示例覆盖所有变体）：

❌ 骨架内混入非屏幕字：

```
┌─ 许可证使用情况（新增·简化版） ─────────┐
│ 席位（独占）：1（独占，固定）            │
│ Agent 实例：3 个 · 独占 · 已使用 1 / 剩 2│
│ 配额（按该产品维度集动态显示）          │
├─ 旧版授权 V1（已吊销，弱化） ───────────┤
│ [▸ 高级配置]   ← 默认值藏在这里        │
└─────────────────────────────────────────┘

[选择来源许可证（多证场景下出现）]
```

✅ 骨架内只写屏幕字 + 解释下沉：

```
┌─ 许可证使用情况 ─────────────────────────┐
│ 席位：1                                  │
│ Agent 实例：3 个 · 已使用 1 / 剩 2        │
│ 配额：32 万 token                        │
├─ 旧版授权 V1（已吊销） ──────────────────┤
│ 共享部门：研发部 / 产品部                │
│ 范围：仅本部门  [改为共享部门额度]       │
└──────────────────────────────────────────┘

[选择来源许可证]
```

**关键交互说明**（骨架下方文字段，承载所有被剥离的注释）：
- 「许可证使用情况」区块在 task-XXX 新增；展示形态延续 task-YYY 的多维度透明展示模式
- 「席位」字段对所有产品恒为独占占用（系统保证）；UI 不重复标注
- 「配额」字段按产品配置的多种计量维度动态展示（token / 调用次数 / 存储 GB 等）
- 「旧版授权 V1」区块视觉弱化（具体视觉规范见 `docs/DESIGN.md`）
- 「改为共享部门额度」按钮：席位默认为独占，仅当 admin 显式切换为共享时进入共享部门选择流程
- 「选择来源许可证」入口仅在多证场景出现（admin 名下持有该产品 ≥2 个许可证时）

**5 类失败模式都是这条规则的应用**：

| 失败模式 | 错在哪 | 怎么改 |
|---|---|---|
| 默认值标注（"席位（独占）"） | 系统恒定属性，屏幕字本身没有这个标 | 直接写值，元数据进 §交互说明 |
| 文档元注释（"（新增·简化版）"） | 给文档读者看的，admin 看不见 | 完全删除（变更范围说明在 §📋 / §🔄 已有） |
| 设计意图（"（已吊销，弱化）"） | 给设计师/工程师的实现指令 | 文案保留状态名「已吊销」；视觉弱化进 §交互说明，引 `docs/DESIGN.md` |
| 字段口径（"（多证场景下出现）"） | 给读者解释字段定义 | 屏幕字保留入口名；触发条件进 §交互说明 |
| 折叠藏默认值（"[▸ 高级配置]"） | 默认值伪装成扩展项 | 默认值直接渲染；override 走单独按钮（如「改为共享部门额度」） |

**自动 lint 边界**：`check-doc-pm-view.py` 仅对骨架代码块内出现的 `（...）` 报 warning（不区分类型）。warning 不阻塞，由 PM/AI 自判是合法标识型（CSV / 1080p / 2 个）还是非法释义型（基于 X / 按 Y / 多 Z 场景）。其余 4 类失败模式 lint 抓不全，靠步骤 5 自检 + reviewer。

### 3.10.1 骨架宽度硬约束

ASCII 框图模式下，骨架代码块每行 ≤ 80 字符（约 78 列内容 + 2 列 border）。

**为什么**：标准 viewport（VS Code preview / 飞书 / Notion / GitHub）能在不水平滚动的前提下完整显示；超过 80 字符时部分渲染器会强制折行，box 字符与中文全宽字符混合 wrap，列对齐崩塌（v3.5 实证）。

**超出 80 字符的常见原因 + 修法**：

| 原因 | 修法 |
|---|---|
| 紧凑行用了完整业务名（"Agent 实例数 / API 调用次数 / 图片生成插件"） | 改用维度简称（席位 / Agent / API / 图片 / 美元）——简称是 80 字符硬约束派生的命名约定，与"产品详情页 Tab 1 池行" convention 对齐 |
| 单行塞太多字段 | 拆成多行（header 行 + 数据行）；每行只放一个语义单元 |
| 列宽设置过大 | 列名长度不超过对应数据最大长度 + 2 字符 |

**渲染兜底**：即便 ≤ 80 字符也可能在某些 markdown 渲染器（不识别代码块 monospace）下挂掉。如果你的渲染器对 ASCII 框图不友好，换用 VS Code preview / Obsidian / Typora 等支持 monospace 的 viewer 看。框架不再为非 monospace 渲染器降级——保留 ASCII 框图的 PM 直觉价值。

## 3.11 禁用版本 / 迭代过程语言

PM 视图文档（solution / prd / analysis 等）描述的都是**最终产物形态**，读者不应感知中间迭代过程。所有"v1 / v2 / 重做 / 重构 / 第二代 / 下一版 / 老版 / 新版 / 主战场 / 整个 v2 范围内 / v2 整体重做"一律不写。

| 类别 | ❌ 错误 | ✅ 正确 |
| --- | --- | --- |
| 标题 / 章节用版本号 | "...重审 v2"  / "...重构方案" | "...PRD" / "...功能清单"（直接说最终产物） |
| 描述用过程语言 | "整体重做方案" / "重构后的体验" | "...功能需求" / "支持..." / "覆盖..." |
| 范围限定用版本 | "整个 v2 范围内" / "全 v2 范围" | "本文档范围内" / "本模块范围内" |
| 模块定位用迭代版本 | "X = v2 主战场" / "第二代体验" | 删除或改为"主操作页" / "主功能" |

例外：文档版本信息 / 变更日志（这是文档自身的版本号）；产品名版本（如"万智平台 2.1"）作为产品名一部分时可保留。

## 3.12 描述风格规则（req-003 PRD 修订经验沉淀）

适用：所有 PM 视图层文档,但 PRD §六 表格 / §五 用户故事 / §4.1 业务诉求 等 prose 段最常踩。lint `scripts/check-prd-hierarchy.py` 类 2 全篇扫描机械违规;LLM 在生成时按本段 framework 自检。

### 3.12.1 判定 framework：生僻描述词 = 工程黑话

PM 风格的核心判定标准：**读 PRD 时是否需要二次理解？需要 → 生僻 = 工程黑话**。一般 PM 在自然写作中不会用的词都属于此类。下列六类违规均按此 framework 判定。

### 3.12.2 禁用视觉细节越界（DESIGN.md 范畴）

PRD 写**业务行为**（"warning 形态二次确认 / 影响范围摘要 / 不可逆操作需输入文字防呆"），不写**视觉实现**（颜色 / 图标颜色 / 按钮变体 / 视觉弱化形式 / 字体粗细）。视觉由 DESIGN.md 或原型决定,PM 在 PRD 定稿后会自己补图。

| 子类 | ❌ 错误 | ✅ 正确 |
| --- | --- | --- |
| 颜色 hex | "取消用红色 #CB2634" | 删 (颜色由 DESIGN.md 决定) |
| 图标颜色 | "橙色 warning 警示图标" | "warning 形态二次确认" (保留破坏性等级,删图标颜色) |
| 按钮颜色变体 | "红色按钮" / "ghost 按钮" / "明文按钮" | 直接 `[按钮名]`,不修饰 |
| 按钮填充 | "destructive 红色填充" / "默认主色填充" | 删 (保留"轻档 / 中档 / 重档"业务分级) |
| 视觉弱化 | "整段视觉弱化" / "行整体视觉弱化" | "失效证只展示段头,不展示操作按钮" (说清行为约束让设计自己决定) |
| Badge | "状态 Badge" / "Badge 红色" | "状态标识" 或删 |
| 字体强调 | "「不可逆」三字加粗加红色强调" | "「不可逆」需视觉强调" 或删 |

### 3.12.3 禁用 URL 路由 / 技术实现细节

PRD 写**业务行为**（"管理员可一键切换两种视角" / "支持深链直达指定视角"），不写**路由实现**（URL 参数 / 路由占位符 / 图标 Unicode 字符）。

| 子类 | ❌ 错误 | ✅ 正确 |
| --- | --- | --- |
| URL 参数 | "URL `?view=dept`" / "?tab=pools&view=license" | 删 |
| 路由占位符 | "`/tenant/products/<productId>?...&license=<licenseId>`" | 删 |
| 图标字符 | "▾↔▸ 点击切换" / "段头支持折叠展开 (▾↔▸)" | "段头支持折叠展开" (不写图标具体形态) |
| 通用 UI 词 | TAB / 弹窗 / 抽屉 — **保留** (通用业务词,不是工程黑话) | 保留 |

### 3.12.4 禁用排版分隔符越界

PRD 写"展示哪些字段",不写"字段间用什么符号分隔"。

| 子类 | ❌ 错误 | ✅ 正确 |
| --- | --- | --- |
| 中点 `·` 分隔字段 | "产品名 · 产品 ID · 状态 · 操作" | "产品名、产品 ID、状态、操作" (用顿号或自然句) |
| `+` 拼接列表 | "席位 + Agent + API + 美元" | "席位、Agent 实例数、API 调用次数、美元" |
| 中文方角引号 | "「按部门查看」段头" | `"按部门查看"`段头 |

### 3.12.5 禁用否定式描述（暴露否决方案）

PRD 只描述当前方案。"无 ⋮ 菜单" / "不再 X" / "不是 destructive" 等写法把已被否决的设计暴露给读者,读者要先脑补这些否决方案才能理解当前设计。

| ❌ 错误 (暴露否决方案) | ✅ 正确 (直接描述当前) |
| --- | --- |
| 已激活证池行展示 [调整分配] [取消分配],**无 ⋮ 菜单** | 已激活证池行展示 [调整分配] [取消分配] |
| 弹窗只保留文件上传入口 (**不再有**"字符串粘贴入口") | 弹窗中只提供文件上传入口 |
| **不再展示**"适用租户"字段 | 删 (直接不写就是不展示) |
| **不再拆为**"授权产品列表"+"许可证使用情况"两个独立区块 | "产品授权项 & 使用情况"为单一合并区块 |
| `[确认停用]` 按钮使用默认主色填充 (**不是 destructive 红色**) | 删 (视觉细节本身就该删) |
| 弹窗顶部**无警示图标、无破坏性色调** | 弹窗为轻档二次确认形态 |

注意区分:
- ❌ **否决式** ("无 X" / "不再 X" / "不是 X") 暴露设计过程 → 删
- ✅ **边界声明** ("部门管理员视角下不展示" / "失效证不在候选项中") 描述当前行为 → 保留

### 3.12.6 禁用工程黑话 / 抽象学院派命名

按"生僻描述词 = 工程黑话"判定。常见工程黑话词典:

| 工程黑话 | 业务语言 |
|---|---|
| 触发 ("触发弹窗") | 点击后打开 / 点击后可 X |
| 锚定 | 定位到 / 跳转到 |
| 池行末 / 行末 / 顶部右侧 / 顶部右上 | 每一行额度池 / 列表顶部 / 页面顶部 |
| 紧凑形态 / 简化形态 / 折叠形态 | 删 (PM 补图) |
| Drawer / Dialog (独立的 UI 部件名) | 弹窗 / 抽屉 (中文通用词) |
| destructive / warning / ghost (作为颜色 / 形态描述) | 重档 / 中档 / 轻档 (破坏性等级) |
| 同口径 | 一致 / 数字相同 |
| 漂移 | 不一致 |
| focus trap | 焦点收敛在弹窗内 |
| disabled | 置灰 / 不可点 |
| loading | "加载中..." / "校验中..." |
| remove (英文) | 删除 |
| 池树 | 删 (具体说明展示什么) |
| 联动 (独立的"按 X 联动") | "按 X 状态显示 / 隐藏" / "X 改变时 Y 自动跟着变" |
| 账本 (账本记录 / 账本数字 / 许可证级账本) | 记录 / 数字 / 累计数字 |
| 跟随失效 (抽象动作短语) | 一并失效 / 也一并失效 / 因 X 失效而失效 |
| 承载 ("由 X 承载") | "X 包含" / "由 X 提供" |
| 全貌 ("完整使用全貌") | 删 (直接陈述对象,如"完整使用情况") |
| 一步可达 | 删 / "点击 [详情] 即可查看" |
| 不承载 (写动作) ("详情不承载写动作") | "详情只用于查看" |
| 绕过 X 中介 | "不走 X 这一层" |

**抽象学院派命名 (凝练黑话)**：§4.2 设计原则名、二级 / 三级功能名、模块引语等位置不允许凝练抽象 4-6 字短语。读者光看名字读不出含义,必须查内容才反推 → fail。

| ❌ 凝练抽象 (违规) | ✅ 自然短句 (PM 风格) |
|---|---|
| 显式归因 | 每一笔分配和开通都关联一张许可证 |
| 多维度对称 | 所有维度按相同结构分账和分配 |
| 双视角对等 | 按部门和按许可证两个视角都能查看额度 |
| 状态联动 | 许可证失效时部门额度池和已开通用户一并失效 |
| 防误分档 | 高风险操作按破坏性程度分三档二次确认 |
| 凭证执行分离 | 许可证管理只看凭证 / 产品访问管理负责执行 |

### 3.12.7 描述视角：业务行为，不下指令

PRD 是产品规格描述,不是给读者的 how-to 指南。**禁用 PM 指令视角** ("想 X 请走 Y" / "如果你 X,请 Y"),改为**业务行为描述视角** ("清空 X 通过 Y 操作" / "X 由 Y 完成")。

| ❌ 指令视角 | ✅ 业务行为视角 |
| --- | --- |
| 想清空请走"取消分配" | 清空部门额度池需通过"取消分配"操作 |
| 想恢复请重新开通 | 恢复访问需重新开通 |
| 请先撤销已有记录再重新开通 | 已有记录需先撤销,然后才能重新开通 |

### 3.12.8 流程式步骤要求

涉及多步操作 (弹窗填写、功能流程) 时,先用 "先 X → 再 Y → 然后 Z → 最后 W" 明确流程概述,再用独立条目展开每步细节。**禁止**把流程步骤、过滤规则、字段细节混在一个长复合句里。

| ❌ 流程混杂 | ✅ 流程式 + 细节分条 |
| --- | --- |
| 弹窗内先选目标部门,再选来源许可证 (单证场景自动选定...多证场景展示候选项,每行展示...),再填多维度数字。多维度数字输入区按当前产品维度集动态生成;不可分配状态的证不展示在候选项中。 | 1. 弹窗的填写流程:先选目标部门 → 再选来源许可证 → 最后填多维度数字。<br>2. 选证规则:单证自动选定;多证展示候选项 (许可证名、状态、有效期、剩余多维度数字);已失效或不可分配的证不展示。<br>3. 多维度数字输入区按当前产品维度集动态生成。 |

### 3.12.9 精简原则

精简优先级 (按效果从高到低):

1. **删可推导信息**:上一条已说"两组:A 组 + B 组",下一条不需要再说"管理员可在 A 组和 B 组之间切换"
2. **删技术细节括号**:"(候选范围 = 选定用户所属部门 ∩ 该产品挂载的部门额度池)" 改成自然语言"该用户所属部门下、该产品的所有部门额度池"
3. **删冗余说明**:"弹窗有两个入口:本入口 (无预选) 和 X 入口 (默认预选 Y),两个入口打开同一弹窗" 改成"提供 X 按钮,点击后打开弹窗;Y 按钮也打开同一弹窗,并默认预选 Y"
4. **长复合句拆条**:一句话里 3 个以上分号 → 拆成多个独立条目
5. **删冗长错误文案**:长 UI 错误文案改成业务摘要"先撤销已有记录再重新开通",详细文案设计阶段决定
6. **删举例细节**:"子部门 (如"前端组") 与一级部门 (如"技术部")" 改成"子部门与一级部门"

### 3.12.10 UI 元素指代与引号风格

涉及按钮 / 弹窗 / 提示行为的描述,必须明确:

- **按钮名**:用方括号 `[...]` 包按钮上的具体文字 (如 `[添加用户]` 按钮)。
- **状态名 / 字段名 / 卡片名 / 区块名 / 文案**:用 ASCII 双引号 `"..."` (如 `"已开通用户数"`列、`"产品授权项 & 使用情况"`区块)。
- **禁用** `「」` (中文方角引号)。

| ❌ 错误 | ✅ 正确 |
| --- | --- |
| 「按部门查看」段头 | `"按部门查看"`段头 |
| 「分配额度到部门」按钮 | `[分配额度到部门]` 按钮 |
