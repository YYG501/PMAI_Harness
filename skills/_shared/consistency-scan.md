# 共享方法论：一致性扫描

规格和原型会漂移：改原型时忘了同步规格，或同步规格时悄悄丢了内容。这份扫描是**写规格 / 改原型时顺手跑的轻行为**，把对不上的地方 flag 出来让 PM 拍，**不静默吞、不盲目重写**。

它**不是强制门**——是 `/pmai-design` 和 `/pmai-close` 自带、任何编辑都能顺手调的自检。守红线：不挡流程、不自动改。

---

## 什么时候扫

- **改了原型** → 扫一遍，看规格要不要跟着改。
- **改了规格** → 扫一遍，看原型 / DESIGN / 术语表有没有对不上的。
- **`/pmai-close` merge 那一刻** → 做一次"老规格 vs 新原型"对账（这是治 drift 的关键时刻，单独说，见第四块）。

简单到一两行的小改、纯文案错字，不用每次都扫——AI 临场判断改动是否触及字段 / 规则 / 概念 / 状态，触及了才扫。

---

## 怎么扫（三步）

### 第一步 · 定位改动点

这次改动碰了什么：某个字段？某条规则？某个概念 / 术语？某个状态？把它们列出来当扫描锚点。

### 第二步 · grep 相关文档

拿锚点去相关文档里搜，看几处口径对不对得上：

- **规格** `docs/modules/<模块>/spec.md` —— 这个字段 / 规则在规格里怎么定义的？
- **原型** `prototype/`（按 `input-flow.md §9.3.1` 选读，别整文件 Read 大文件）—— 原型里实际是怎么实现的？
- **DESIGN.md** —— 涉及视觉 / 组件的，DESIGN 里的约定还对得上吗？
- **术语表** `docs/PRODUCT.md` 业务术语表 —— 改了某个词，有没有近义词散落各处该统一？

可以借框架现成脚本辅助（都是 advisory、`|| true`，不阻塞）：

```bash
# 索引漂移：docs/ 实存文档 vs PRODUCT-STATE 索引（顶层文档漏挂）
python3 "$PMAI_HOME/scripts/check-state-index-drift.py" "$REPO_ROOT" || true
```

脚本只覆盖机械可查的部分（索引漏挂）；规格 ↔ 原型 的语义对账靠 AI grep + 读，脚本兜不住。

### 第三步 · flag，不静默吞

每处对不上的，**摊给 PM 让他拍**，分三类：

1. **规格说 X、原型现在 Y → 哪个对？** （口径打架，PM 定准哪个是真相，另一个跟着改。）
2. **这条规格在原型里找不到对应了 → 有意删（同步删规格）还是漏实现（补回原型）？** —— **这条是治 drift 的关键**。规格里写过、原型里没有，两种可能：要么是 PM 有意砍了这个功能（那规格也该删 / 标 supersede），要么是漏实现了（那得补回去）。绝不能默认"原型没有 = 规格写错了"就把规格悄悄删掉——那正是 PM 抱怨的"review 原型时规格信息被悄悄删"。
3. **改了某个术语 → 散落各处的近义词要不要统一？**

flag 用 PM 看得懂的话说，不出"drift / 漂移"这类内部词。例：

```
对了一下规格和原型，有两处对不上，你来定：

1. 规格写"额度超限时拦截并提示"，原型里现在是直接报错没提示文案 —— 哪个算数？
2. 规格里"批量导入"这条，原型里没找到对应页面 —— 是这个功能砍了（那我把规格也删掉），还是还没建（那留着，记一笔待建）？
```

---

## 四、`/pmai-close` 时的老规格 vs 新原型对账（治 drift 的关键时刻）

`/pmai-close` 把 worktree 改动 merge 回 main、定稿规格那一刻，是规格最容易被"悄悄删内容"的地方——因为这时要拿最终原型回头校准规格，一不小心就把"原型没体现的规格条款"当噪声删了。

对账纪律：

- **逐条过老规格**：老规格里每一条，在新原型里找得到对应吗？
- 找不到对应的，**不盲目重写、不默默删**——按上面第三步的第 2 类 flag："这条确认删（功能砍了）还是漏实现（该补回）？"PM 拍。
- 确认删的，在 `decisions.md` 标 supersede（留"为什么删"），不是假装没写过。
- 确认漏实现的，留在规格里 + 记一笔进 `TODO.md` 或模块 `.work-meta`，别让它消失。

**根除**："规格信息被 review 悄悄删掉"——靠的就是这一刻每条都摊出来让 PM 拍，而不是 AI 替 PM 判"原型没有所以这条不要了"。

---

## 边界（守红线）

- **不升格成强制门**：这是 silent 自检 + 顺手 flag，不挡 `/pmai-design` / `/pmai-close` 的流程，不要求"扫完无 drift 才能继续"。
- **AI 不自动改**：扫描只 flag，改不改、怎么改 PM 拍。尤其"原型没有的规格条款"——绝不自动删。
- **不引入新脚本系统**：复用 `check-state-index-drift.py` 这类已有 advisory 脚本；语义对账靠 AI grep + 读，不为这事新造强制校验工具。
