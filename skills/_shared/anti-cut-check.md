# 共享参考：对抗三问（减法决策强制门）

## 一句话

每做一个**减法**（砍 / 合并 / dormant / collapse / 简化 / 折叠），当场答**对抗三问** + 用**对称判别尺**判一次，把**三行自答**写进对应记录。答不全不许落盘。

## 为什么有它（别当仪式删掉）

这道门用于防止"砍了流程但没有补能力"的同构错误：探索能力假并入、discussion 顺序倒、磨文字无机制守、build 锚点悬空、决策收家折叠等问题都属于同一类。它把"为什么会犯这个错"制度化成不再犯：删流程前必须先说明能力如何被保留或替代。

## 对抗三问（逐条答，不许跳）

- **(a) 丢了什么？** —— 这个减法具体丢掉了什么能力 / 信息 / 隔离 / 把关？
- **(b) 对所有需求类型都成立吗？** —— 是只对手头这类需求成立、还是对所有类型都成立？（上次"7 步法对任何需求都成立"就栽在这）
- **(c) 是不是把内核当仪式砍了？** —— 砍的是"形态 / 仪式"（强制闸门、目录树、状态机），还是连"能力 / 内核"一起倒了？

## 对称判别尺（两边都要用）

| 砍掉后的现象 | 判定 | 动作 |
|---|---|---|
| 补丁消失 / 流程更顺 / 能力不减 | **仪式税** | 砍对，落盘 |
| 能力消失 / 制造新冲突 / 留下断链 / 把真问题逼回野路子 | **内核** | 别砍；要砍须在自答里写明为何仍砍 |

**两边都要用**：砍错的（内核）捞回来，砍对的（仪式税）别因矫枉过正又捞回来。

## 三行自答（落盘格式）

在对应 `decisions.md` / 理路记录 / dormant 条目里留：

```
减法决策：<砍 / 合并 / dormant 了什么>
(a) 丢了什么 / (b) 对所有类型成立吗 / (c) 形态还是内核：<逐条答>
判别尺结论：仪式税 → 砍 ｜ 内核 → <为何仍砍，或：撤销不砍>
```

## 正面对照（砍对的，别捞回来）

7-stage 流水线 / task 状态机 / 逐层转写链 / requirements 目录树 / 工程双合同——这些 dormant 是**对的**：砍掉补丁消失、能力不减 = 仪式税。判别尺要拦的是"矫枉过正把它们救回来"。

## 反面对照（砍错的，已撤 / 待改）

同构错 6 处（见上）。每一处都是"看到 ExampleAgentProject 几个 skill 够用 → 推断框架对应能力是冗余仪式 → 没过 (a)(b)(c) 就砍"。
