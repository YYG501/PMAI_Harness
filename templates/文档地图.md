# 文档地图（这个项目的文档怎么分类、各住哪、AI 怎么读）

> **核心一句**：当前产品长什么样看 `PRODUCT-STATE`；文档怎么找看 `docs/INDEX.md`；当前模块做什么看模块三件套；PRD / 功能需求 / 功能评审稿进 `docs/modules/*.md`；介绍型材料进 `docs/deliverables/`。

## 一、文档分类表

| 类别 | 住哪 | AI 何时读 | 生命周期 |
|---|---|---|---|
| **现状核心**：产品现状 | `PRODUCT-STATE.md` | 每次进项目先读 | 长期真相源，只在沉淀时写 |
| **文档入口**：消费仓总索引 | `docs/INDEX.md` | 找文档、材料、模块、产物时先读 | 长期维护 |
| **项目脊柱**：定位/角色/术语、视觉规范、跨功能规则、主原型 | `PRODUCT.md` / `DESIGN.md` / `PRODUCT-RULES.md` / `prototype/` | 按需读 | 长期真相源 |
| **项目决策档案**：重大理路冻结档 | `docs/decisions/` | 查"为什么这么定"时按需读 | 写一次、不维护 |
| **当前模块工作**：讨论、决策、规格、状态 | `docs/modules/<模块>/discussion.md` / `decisions.md` / `spec.md` / `.work-meta.json` | 当前工作触及时读 | 模块内就地演进 |
| **功能型规格文档**：PRD、功能需求、功能描述、功能规格、功能评审稿 | `docs/modules/<按内容命名>.md` | PM 要功能型成稿时写；build 可作为功能锚点 | 按内容演进 |
| **输入材料**：PM 上传、调研、竞品、旧文档 | `docs/inputs/<类别>/` | 作为 evidence 按需读；当前模块引用看模块 `.work-meta.json` | 留存，可被多个模块引用 |
| **探索变体（mock）** | `mockups/`（`manifest.json` 是真相源） | 想找回视觉方向时读 | 全部留存；并进主原型的标"已退役" |
| **归档**：一次性 review / 被取代旧稿 / 过程档案 | `docs/archive/` | 不主动翻 | 留底 |
| **介绍型材料**：产品介绍、产品功能清单、产品优势说明、一页纸 | `docs/deliverables/` | PM 要介绍 / 表达材料时写 | 按需 |
| **待办池** | `TODO.md` | 新需求起步时提醒 PM 挑一个 | PM 随手增删；AI 不反推填充 |

## 二、读取入口分层

- **现状核心 = `PRODUCT-STATE.md`**：AI 一进项目就读。它只装当前产品现状。
- **文档索引 = `docs/INDEX.md`**：要找模块、功能型规格文档、输入材料、项目决策档案、介绍型材料时先看它。
- **按范围展开 = `PRODUCT` / `DESIGN` / `PRODUCT-RULES` / `modules/` / `docs/decisions/` + 主原型**：当前范围触及时才读。

## 三、什么进哪里

- **当前现状** → `PRODUCT-STATE.md`
- **模块过程和长期规格** → `docs/modules/<模块>/discussion.md` / `decisions.md` / `spec.md`
- **PRD / 功能需求 / 功能描述 / 功能规格 / 功能评审稿** → `docs/modules/<按内容命名>.md`
- **产品介绍 / 功能清单 / 优势说明 / 一页纸** → `docs/deliverables/`
- **重大项目级"为什么这么定"** → `docs/decisions/<日期>-<slug>.md`

反例：一次性 review、临时分析、被取代旧稿 → `docs/archive/`；PM 上传材料 → `docs/inputs/`；想做没做的 → `TODO.md`。
