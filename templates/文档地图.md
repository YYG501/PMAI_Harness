# 文档地图（这个项目的文档怎么分类、各住哪、AI 怎么读）

> **为什么有它**：单人 PM 没人帮 review，文档一旦"没有明确的家"就逃成野文档、真相源乱、后面的需求读不到前面的关键讨论。这份地图给每类内容钉死一个家，AI 与 PM 都按它归位。
> **谁读**：消费仓 AI 在新建任何文档前先对一眼本表；PM 想知道"这东西该放哪"也看它。
> **核心一句**：**当前产品长什么样看脊柱；为什么这么拼看决策记录；想做没做的看待办池；探索过的视觉变体看 mocks 看版。**

## 一、文档分类表

| 类别 | 住哪 | AI 何时读 | 生命周期 |
|---|---|---|---|
| **脊柱 · 必读核心**：产品现状 hub | `docs/PRODUCT-STATE.md` | **每次进项目先读**（"先读项目底座"入口） | 长期真相源，**每一档沉淀时写**（沉淀是它唯一的写入口；轻量同构，不随手改） |
| **脊柱 · 索引展开**：产品定位/角色/术语、视觉规范、跨功能产品规则、模块规格、**项目决策记录**、主原型 | `docs/PRODUCT.md` / `docs/DESIGN.md` / `docs/PRODUCT-RULES.md` / `docs/modules/` / `docs/decisions/` + `prototype/` | **按需**（被 hub 索引到、或当前需求范围触及才读；决策记录尤其——查"为什么"才读） | 长期真相源，每一档沉淀时写 |
| **探索变体（mock）**：探索期并行原型集 | `mocks/`（`manifest.json` 是真相源 + 生成的 `index.html` 看版导航） | 想找回"之前探过哪些视觉方向"时翻看版 | 全部留存、tracked；并进主原型的标"已退役"**留不删**（看版折叠） |
| **过程（在途）**：本需求的范围确认产物 / 入口稿 / task / 运行时记录 | `requirements/active/<req>/`（`req-plan.md` / `brief.md` / `tasks/` / `.req-meta.json` / events / `attachments/`） | **仅本需求读** | close 后整目录移 `requirements/closed/` |
| **归档**：已关需求、过程档案 / 一次性 review / 被取代的旧文件 | `requirements/closed/<req>/` + `docs/归档/`（扁平单层） | **不主动翻**（知识靠沉淀进脊柱传，不靠检索旧档） | 留底 |
| **产物（按需）**：可评审 PRD / 对外产物 | `requirements/active/<req>/prd.md` / `docs/独立PRD/` / `deliverables/` | 按需 | 按需 |
| **待办池**：PM 提过 / 讨论过想做的事 | `docs/TODO.md` | 新需求起步时提醒 PM 挑一个 | PM 随手增删；**沉淀时"推下个需求"的遗留自动入**（带一句话自包含） |

> 顶层 `docs/` 命名 / 归档规则（什么准放顶层、旧文件怎么 mv 走）见消费仓 `CLAUDE.md` §「docs/ 归档约定」——本表是上层分类模型，那一节是顶层落地细则，两者一致。

## 二、脊柱分两层（读取模型）

脊柱（项目底座）不是平的，分两层，决定 AI 每次载入多少：

- **必读核心层 = `docs/PRODUCT-STATE.md`**：AI 一进项目**就读**。它是"当前产品长什么样"的 hub——现在能做什么、主原型有哪些页面、哪些是真系统哪些还是 mock，外加指向其余脊柱文件的索引。要小、要稳。
- **索引展开层 = `PRODUCT` / `DESIGN` / `PRODUCT-RULES` / `modules/` / `decisions/` + 主原型**：被 hub 索引着，**查到才读 / 范围触及才读**，不每次全载。其中 **`docs/decisions/`（项目决策记录）= 查"为什么这么拼"时才展开**——护城河论证、机制整体设计意图、演进故事住这里（带日期的历史快照，不是活的现状）。

**为什么分两层**：全塞进必读核心 → 每次进项目载一大坨、噪声高；全推到按需 → 关键理路"按需 = 实际从不"被读到。分层让现状每次都在手边、理路在范围触及时主动浮出来。

## 三、什么够格当脊柱（扩展判据）

新内容想进脊柱时，按它要进哪一层套判据：

- **想进必读核心层**：问"删了它，AI 还懂不懂当前产品？"——**影响 → 进**（说明它是现状的一部分）；不影响 → 不进（推到索引展开或别的类别）。门槛高，必读核心要小。
- **想进索引展开层**：是不是**长期真相源**（当前现状 / 规则 / 视觉 / 模块规格 / 项目级理路）？是 → 进，被 hub 索引、按需读；否 → 它属于"过程 / 归档 / 待办 / 产物"，按一表归位，不污染脊柱。

> 反例（**不进脊柱**）：一次性 review、过程分析、被取代的旧稿 → `docs/归档/`；某个需求在途的范围 / task → `requirements/active/<req>/`；想做没做的 → `docs/TODO.md`。
