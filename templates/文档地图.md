# 文档地图（这个项目的文档怎么分类、各住哪、AI 怎么读）

> **核心一句**：当前产品长什么样看脊柱；为什么这么拼看决策记录；当前模块做什么看模块三件套；输入材料进 `docs/inputs/`；探索过的视觉变体看 `mocks/`。

## 一、文档分类表

| 类别 | 住哪 | AI 何时读 | 生命周期 |
|---|---|---|---|
| **脊柱 · 必读核心**：产品现状 hub | `docs/PRODUCT-STATE.md` | 每次进项目先读 | 长期真相源，只在沉淀时写 |
| **脊柱 · 索引展开**：产品定位/角色/术语、视觉规范、跨功能规则、模块规格、项目决策记录、主原型 | `docs/PRODUCT.md` / `docs/DESIGN.md` / `docs/PRODUCT-RULES.md` / `docs/modules/` / `docs/decisions/` + `prototype/` | 按需读 | 长期真相源 |
| **当前模块工作**：讨论、决策、规格、状态 | `docs/modules/<模块>/discussion.md` / `decisions.md` / `spec.md` / `.work-meta.json` | 当前工作触及时读 | 模块内就地演进 |
| **输入材料**：PM 上传、调研、竞品、旧文档 | `docs/inputs/<类别>/` | 作为 evidence 按需读 | 留存，可被多个模块引用 |
| **探索变体（mock）** | `mocks/`（`manifest.json` 是真相源） | 想找回视觉方向时读 | 全部留存；并进主原型的标"已退役" |
| **归档**：一次性 review / 被取代旧稿 / 过程档案 | `docs/归档/` | 不主动翻 | 留底 |
| **产物（按需）**：可评审 PRD / 对外产物 | `docs/独立PRD/` / `deliverables/` / PM 指定路径 | 按需 | 按需 |
| **待办池** | `docs/TODO.md` | 新需求起步时提醒 PM 挑一个 | PM 随手增删；AI 不反推填充 |

## 二、脊柱分两层

- **必读核心层 = `docs/PRODUCT-STATE.md`**：AI 一进项目就读。它是"当前产品长什么样"的 hub。
- **索引展开层 = `PRODUCT` / `DESIGN` / `PRODUCT-RULES` / `modules/` / `decisions/` + 主原型**：被 hub 索引着，查到才读 / 范围触及才读。

## 三、什么够格当脊柱

- **想进必读核心层**：问"删了它，AI 还懂不懂当前产品？"影响当前理解才进。
- **想进索引展开层**：是不是长期真相源（现状 / 规则 / 视觉 / 模块规格 / 项目级理路）？是才进。

反例：一次性 review、临时分析、被取代旧稿 → `docs/归档/`；PM 上传材料 → `docs/inputs/`；想做没做的 → `docs/TODO.md`。
